## 1. `src/roles.rs`
```rust
pub struct RoleResolver { /* cache: Mutex<HashMap<(String /*app*/, i64 /*config version*/, String /*uid*/), (Option<String>, Instant)>> */ }
impl RoleResolver {
    pub fn new() -> Self;
    /// Resolves the role of an already verified identity. Never caches errors.
    pub async fn role(&self, app: &str, version: i64, policy: &IdentityPolicy, identity: &Identity, source: &dyn DataSource) -> Result<Option<String>, RoleError>;
}
pub enum RoleError { Unavailable(String) }
```
- `IdentityPolicy` = ما يلزم من `config::Identity` (role source + admin_roles) أو مرّر `&config::Identity` مباشرة؛ اختر الأبسط. للتطبيق بلا إعداد ابنِ سياسة افتراضية ثابتة: `Claim`-less ⇒ `DataSource{doc:"users/{uid}", field:"role", cache_seconds:60}` و`admin_roles:["admin"]`.
- `RoleSource::Claim{claim}`: `claim_at(&identity.claims, claim)`؛ نص غير فارغ ⇒ الدور؛ غير ذلك (غير موجود/مصفوفة/رقم) ⇒ `None` (وثّق في تعليق أن المصفوفات غير مدعومة).
- `RoleSource::DataSource{doc,field,cache_seconds}`: استبدل `{uid}` في `doc` بالـuid (التحقق يتم داخل `validate_doc_path` للمصدر؛ لا تُرمّز بنفسك)، `get_doc`؛ `None` ⇒ دور `None`؛ حقل `field` (مسار نقطي) نص غير فارغ ⇒ الدور، وإلا `None`. `DataError` بأي نوع ⇒ `RoleError::Unavailable("role lookup failed")` (لا تُسرّب رسالة المصدر للعميل؛ سجّل التفصيل بـ`tracing::warn!` دون uid كامل إن أمكن).
- المخبأ: TTL = `cache_seconds` (0 ⇒ بلا تخزين)، حد أقصى 4096 مدخل (عند الامتلاء نظّف المنتهي ثم امسح الكل)، المفتاح يتضمن `version` فيبطل بتغيّر الإعداد. لا تُمسِك القفل عبر `await`. الأدوار `None` تُخزَّن أيضاً (سلبي) بنفس الـTTL.
- `pub fn is_admin_role(role: Option<&str>, admin_roles:&[String]) -> bool`: تطابق **حرفي حساس لحالة الأحرف**، قائمة فارغة ⇒ false دائماً.
- مطابقة الاشتراك: `pub fn topic_matches(pattern:&str, topic:&str)->bool`: نمط بلا `*` ⇒ مساواة تامة؛ نمط ينتهي بـ`*` (فقط في النهاية) ⇒ البادئة قبله + جزء لاحق **غير فارغ** كله `[A-Za-z0-9_-]`؛ `*` وحدها أو في الوسط ⇒ لا تطابق أبداً (دفاعاً؛ التحقق يمنعها أصلاً).

## 2. `AuthService` في `auth.rs`
- الدالة `new` تصبح: `new(project_map, identity: Arc<IdentityRegistry>, datasource: Arc<DataSourceRegistry>, config: Arc<ConfigStore>, auth_config: AuthConfig)` (+ المحلّل داخلياً). **احذف** `FirebaseVerifier` المحلي إن وُجد، و`FirestoreReader`/`FirestoreHttp`/`role_is_admin`/`admin_cache` وكل ما صار ميتاً. اترك أي شيء لا يزال مستعملاً (مثل `encode_path_segment` إن استُعمل). لا تترك `#[allow(dead_code)]` جديداً، وأزل القديمة التي لم تعد لازمة.
- `authenticate_admin(headers, app)`: مفتاح الخدمة كما هو؛ ثم `provider_for(app)` ⇒ `verify(token)` ⇒ الدور ⇒ `is_admin_role` وإلا `Forbidden("the user is not an admin for this app")`. نفس رموز الحالة الحالية (401/403/503/404).
- `authenticate_send`: بلا تغيير في منطق المفتاح القديم/الخدمة.
- `authenticate_user(headers, app)`: عبر المزود؛ فشل ⇒ `None` كما اليوم.
- `is_admin(app, uid)` الحالي كان يحتاج uid فقط؛ صار يحتاج هوية كاملة (للـclaim). غيّر توقيعه إلى `is_admin_identity(app, &Identity)` وحدّث المستدعين.
- `authenticate_admin_any(headers)` (للمسارات بلا `app`): كان يختار التطبيقات المرشحة من `aud` غير الموثّق. عمّمه: المرشحون = التطبيقات في `project_map` ∪ `config.app_names()` (إن لم توجد دالة مناسبة في `ConfigStore` فتوقف واذكر ذلك — لا تعدّل `src/config`؛ يمكنك بدلاً من ذلك تمرير قائمة التطبيقات من `project_map` فقط وتوثيق أن تطبيقاً بلا credentials لا يمكنه إرسال أصلاً). الانتقاء المسبق قبل التحقق: لتطبيق Firebase (أو بلا إعداد) تطابق `aud` غير الموثق مع `project_id`؛ لتطبيق JWT طابق `iss` غير الموثّق مع `iss` المضبوط في الإعداد (اقرأ `ProviderConfig` في `src/config/mod.rs`). لا تتحقق أبداً من توكن مقابل أكثر من 8 تطبيقات مرشحة (اقتطع بترتيب أبجدي وسجّل warn). التوقيع يُتحقق دائماً قبل أي بحث عن دور. النتيجة: قائمة التطبيقات التي المستخدم أدمن فيها، وإلا 403 كما اليوم.
- `authorize_topic(headers, app, topic)`: نفس المنطق لكن: مفتاح الخدمة ⇒ Admin؛ هوية صالحة ⇒ إن سمحت `signed_in`+`anonymous` للموضوع ⇒ `User`؛ وإلا إن الدور أدمن ⇒ `Admin`؛ وإلا 403. بلا هوية صالحة ⇒ `anonymous` فقط. فشل الدور (503) يُرجَع فقط حين يلزم الدور (أي حين لا يكفي `User`)، كما اليوم.
- سياسة الاشتراك: `topic_allowed` تصبح تأخذ `Option<&WebSubscribe>`: `None` (تطبيق بلا إعداد) ⇒ **السلوك القديم حرفياً** (`is_public_topic` الصارمة + الثلاثة الثابتة)، و`Some(ws)` ⇒ `anonymous` = تطابق أي نمط في `ws.anonymous`، و`User` = `anonymous` ∪ `signed_in`. القيم الثابتة `users|companies|technicals` **تُزال من الكود** وتبقى فقط كقيمة افتراضية لحالة `None` (ثابت مسمّى `LEGACY_SIGNED_IN_TOPICS`). `Admin` يسمح بكل موضوع صالح كما اليوم.
- `AppState` (`main.rs`): أضف `identity: Arc<IdentityRegistry>` و`datasource: Arc<DataSourceRegistry>` (يُستعملان في T6)، وابنهما في `main()` ومرّرهما لـ`AuthService`. أزل `#[allow(dead_code)]` عن `config` إن صار مستعملاً. عدّل `test_state()` في `src/admin/mod.rs` بالحد الأدنى فقط. خذ `SystemEnv` من `crate::identity::jwt` كما في سجلات T3/T4.
- `topics.rs`: عدّل الاستدعاءات لتتوافق مع التوقيعات الجديدة فقط.
