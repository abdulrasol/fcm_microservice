## 2. نماذج البيانات (`src/config/mod.rs`)
كلها `#[derive(Serialize, Deserialize, Clone, Debug, PartialEq)]` و`#[serde(deny_unknown_fields)]`، ومطابقة للمثال في الخطة 3.2 حرفياً.
- `AppConfig { identity, data_source, devices, web_subscribe, campaigns, app_check }` (القوالب منفصلة: `BTreeMap<String, Template>`).
- `Identity { provider: IdentityProvider, role: RoleSource, admin_roles: Vec<String>, role_members: Option<RoleMembers> }`
- `IdentityProvider`: enum موسوم بـ `type`: `firebase` | `jwt{ algorithms, jwks_url?, hs256_secret_env?, issuer, audience, uid_claim(default "sub"), name_claim?, max_age_seconds(default 3600) }`. الخوارزميات enum يقبل `RS256|ES256|HS256` فقط (`none` يفشل عند deserialize).
- `RoleSource`: `claim{ claim }` | `data_source{ doc, field, cache_seconds(default 60) }`.
- `RoleMembers { collection, field, cache_seconds(default 300), max(default 50) }`
- `DataSource`: `firestore` | `http{ base_url, secret_env, timeout_ms(default 3000) }` | `none`.
- `Devices { max_per_uid(default 5) }`، `WebSubscribe { anonymous: Vec<String>, signed_in: Vec<String> }`، `AppCheck { mode: off|monitor|enforce, project_number: Option<String> }`.
- `Template { description, enabled(default true), senders, params: BTreeMap<String,Param>, context: Option<Context>, vars: BTreeMap<String,Var>, to: Target, title, body, image: Option<String>, data: BTreeMap<String,String>, dedupe: Option<Dedupe>, rate: Option<Rate> }`
- `Param`: `text{max}` | `pattern{pattern,max?}` | `enum{values}` | `int{min?,max?}`. `Context{doc, require: BTreeMap<String,String>}`. `Var{from, map: BTreeMap<String,String>}`. `Target`: `uid(String)|role(String)|topic(String)|condition(String)`. `Dedupe{key,seconds}`, `Rate{per_uid_per_hour}`.
- `Campaigns { enabled, senders, entity: Entity{param,doc,require,name_field}, audience: Audience{allowed_topics,required_topic,max_topics}, content: Content{title_prefix,title_max,body_max,forbid_links,image_hosts,actions: BTreeMap<String,Action>}, quota: Quota{per_entity_per_day,per_entity_per_week}, review: Review{mode:none|always|first_n, n: Option<u32>} }`، و`Action{ params(default empty), check: Option<Check{doc,require}>, data: BTreeMap<String,String> }`.
- `ConfigDocument { version: u32, #[serde(flatten)]... }` لصيغة الاستيراد/التصدير: `{version:1, identity, data_source, devices, web_subscribe, templates, campaigns, app_check}`. اكتبها صراحةً بدل flatten إن سبب مشاكل.
- `AppConfig::default_firebase()`: هوية `firebase`، دور من `data_source` (`users/{uid}`, حقل `role`)، `admin_roles:["admin"]`، مصدر `firestore`، `max_per_uid:5`، `web_subscribe` فارغان، حملات `enabled:false`, `app_check: off`.
  (ملاحظة: `campaigns` عند `enabled:false` تُتجاوز بقية حقولها في التحقق، لكن يجب أن تكون قابلة للتمثيل بقيم افتراضية معقولة.)

## 3. محلل القوالب النصية (`placeholder.rs`)
`pub fn extract(s:&str) -> Result<Vec<Placeholder>, String>` حيث `Placeholder{ r: Ref, int_filter: bool }` و`enum Ref { Param(String), Sender(SenderField), Doc(String), Entity(String), Var(String) }`، `SenderField::{Uid,Name,Role}`.
- الصيغ: `{p.NAME}` `{sender.uid|name|role}` `{doc.PATH}` `{entity.PATH}` `{VARNAME}` وفلتر اختياري `|int` بعد المرجع (`{doc.total|int}`).
- NAME/VARNAME: `[a-z][a-z0-9_]{0,29}`. PATH: مقاطع `[A-Za-z_][A-Za-z0-9_]*` تفصلها نقطة، حتى 5 مقاطع.
- أي `{` بلا إغلاق صحيح، أو `}` يتيمة، أو محتوى غير مطابق، أو فلتر غير `int` ⇒ `Err` برسالة تحدد الموضع. لا أحرف هروب (لا تُدعم أقواس حرفية).
- `pub fn is_literal(s)` ترجع true إذا لا placeholders.

## 4. التحقق (`validate.rs`)
`pub struct Issue { pub path: String, pub message: String }` (path بنقاط مثل `templates.order_new.to`).
`pub fn validate_all(cfg:&AppConfig, templates:&BTreeMap<String,Template>) -> Vec<Issue>` تُرجع **كل** الأخطاء (لا تتوقف عند الأول).
`pub fn validate_template(key, tpl, cfg) -> Vec<Issue>` و`validate_section_shape` حسب الحاجة. القواعد (كل قاعدة لها رمز في الرسالة بين قوسين، مثل `[V3]`):

**الهوية والمصدر:**
- [V1] `app` (اسم التطبيق في واجهة المخزن) يطابق `^[A-Za-z0-9_-]{1,40}$`.
- [V2] مزود `jwt`: `algorithms` غير فارغة ولا تخلط HS256 مع RS256/ES256. إذا فيها HS256 ⇒ `hs256_secret_env` مطلوب ويطابق `^[A-Z][A-Z0-9_]{0,63}$` ولا `jwks_url`. غير ذلك ⇒ `jwks_url` مطلوب ويبدأ بـ `https://`. `issuer` و`audience` غير فارغين. `max_age_seconds` بين 60 و86400. أسماء claims مقاطع نقطية صالحة.
- [V3] `admin_roles` وكل `senders` أدوار تطابق `^[a-z0-9_]{1,32}$`.
- [V4] `RoleSource::data_source` و`role_members` يتطلبان `data_source != none`. `role_members.max` بين 1 و200، و`cache_seconds` ≤ 3600.
- [V5] `http`: `base_url` يبدأ بـ `https://` أو (`http://localhost` / `http://127.0.0.1` للتطوير)، `secret_env` يطابق نمط env أعلاه، `timeout_ms` بين 200 و10000.
- [V6] `devices.max_per_uid` بين 1 و20.
- [V7] أنماط topics (`web_subscribe` وغيرها): `^[A-Za-z0-9_.~%-]{1,100}\*?$` أي حرفي أو ينتهي بـ `*` وحيدة.
- [V8] `app_check.mode != off` ⇒ المزود `firebase` و`project_number` أرقام فقط.

**القوالب (key يطابق `^[a-z][a-z0-9_]{0,39}$`):**
- [T1] `senders` غير فارغة. [T2] اسم كل معامل `^[a-z][a-z0-9_]{0,29}$`؛ `text.max` بين 1 و1000؛ `pattern` يُجمَّع بـ `regex::Regex::new` وطوله ≤ 200؛ `enum.values` بين 1 و50 قيمة غير فارغة؛ `int` فيه min ≤ max.
- [T3] كل placeholder في `title/body/image/data.*/to.*/context.doc/context.require.*/dedupe.key/vars.*.map.*`:
  `p.x` ⇒ `x` معرَّف في `params`. `doc.*` ⇒ `context` موجود. `entity.*` ⇒ ممنوع في القوالب. `{var}` ⇒ معرَّف في `vars` (وقيم `vars.map` لا تُشير إلى vars). `vars.*.from` مسار بدون أقواس يبدأ بـ `doc.` أو `p.` أو `sender.`. `title` و`body` غير فارغين.
- [T4] `to` فيه حقل واحد فقط (يضمنه الـ enum).
- [T5] `context`/`vars.from=doc.*` تتطلب `data_source != none`.
- [T6] مفاتيح `data` لا تساوي `from`/`notification`/`message_type` ولا تبدأ بـ `google.` أو `gcm.`.
- [T7] `dedupe.seconds` بين 1 و86400. `rate.per_uid_per_hour` بين 1 و120.
**حواجز الأمان لغير الأدمن** ("غير أدمن" = أي sender ليس في `admin_roles`، وإذا `admin_roles` فارغة فالجميع غير أدمن):
- [G1] `to` من نوع `topic` أو `condition` ⇒ ممنوع وجود معامل `text` في القالب، وممنوع أن يحتوي `to` أي `p.*`.
- [G2] `to.uid` و`to.role` ممنوع أن يحتويا `p.*` (المستلم من `doc/entity/sender` أو حرفي).
- [G3] `rate` إلزامي.
- [G4] إذا وُجد `context` ⇒ `context.require` غير فارغ، وقيمة واحدة على الأقل منه تحتوي `{sender.uid}`.
- [G5] ممنوع `to.topic == "all"` (حرفياً) أو `to.condition` يحتوي `'all' in topics`.
  (القوالب التي كل مرسليها أدمن معفاة من G1..G5.)

**الحملات (إذا `enabled`):**
- [C1] `senders` غير فارغة، و`entity.param` يطابق نمط الاسم، و`entity.doc` يحتوي `{p.<param>}`، و`entity.require` غير فارغ وإحدى قيمه `{sender.uid}`، و`name_field` غير فارغ، وبقية placeholders فيها `p.<param>` أو `sender.*` فقط.
- [C2] `allowed_topics` غير فارغة، كل عنصر يطابق V7 **أو** V7 مع `{p.<param>}` واحد على الأكثر؛ الجزء الحرفي قبل `*` أو `{` لا يقل عن 3 أحرف (يمنع `*` و`a*`)؛ ولا يطابق أي نمط منها `required_topic` نفسه.
- [C3] `required_topic` حرفي يطابق V7 بلا `*`، و`max_topics` بين 2 و5 (يشمل `required_topic`).
- [C4] `title_prefix` يسمح بـ `{entity.*}` فقط. `title_max` 1..200، `body_max` 1..1000. `image_hosts` أسماء مضيف (`^[a-z0-9.-]{3,100}$`، بدون مخطط ولا مسار).
- [C5] `actions` غير فارغة؛ `data` مفاتيحها حسب T6 وقيمها `p.*` معرَّفة في `params` الخاصة بالإجراء أو `entity.param` أو `sender.*`؛ `check` يتطلب `require` فيه `{sender.uid}`.
- [C6] `quota.per_entity_per_day` ≥ 1 و`per_entity_per_week` ≥ اليومي. [C7] `review.mode == first_n` ⇒ `n` بين 1 و50.

## 5. المخزن (`store.rs`)
```rust
pub enum ConfigError { Invalid(Vec<Issue>), Conflict{ current_version: i64 }, NotFound, Db(sqlx::Error) }
pub struct AppSnapshot { pub config: AppConfig, pub templates: BTreeMap<String,Template>, pub version: i64 }
pub struct ConfigStore { /* pool + RwLock<HashMap<String, Arc<AppSnapshot>>> */ }
impl ConfigStore {
  pub async fn new(pool: SqlitePool) -> Result<Self, ConfigError>;           // يحمّل كل شيء، يتجاهل ويسجّل (tracing::error!) أي سجل تالف أو غير صالح
  pub fn get(&self, app:&str) -> Option<Arc<AppSnapshot>>;
  pub async fn create_app(&self, app:&str, actor:&str) -> Result<(), ConfigError>;     // AppConfig::default_firebase()، تكرار ⇒ Conflict
  pub async fn save_section(&self, app, section:&str, value:serde_json::Value, actor, expected_version:i64) -> Result<i64, ConfigError>;
  pub async fn save_template(&self, app, key, def:serde_json::Value, actor, expected_version:Option<i64>) -> Result<i64, ConfigError>;
  pub async fn set_template_enabled(&self, app, key, enabled:bool, actor) -> Result<(), ConfigError>;
  pub async fn delete_template(&self, app, key, actor) -> Result<(), ConfigError>;
  pub async fn restore(&self, app, version_id:i64, actor) -> Result<i64, ConfigError>;
  pub async fn export(&self, app) -> Result<serde_json::Value, ConfigError>;
  pub async fn import(&self, app, doc:serde_json::Value, actor) -> Result<(), ConfigError>; // يستبدل الكل في معاملة واحدة، ينشئ التطبيق إن لم يكن موجوداً
  pub async fn versions(&self, app, section:Option<&str>, limit:i64) -> Result<Vec<VersionRow>, ConfigError>;
}
```
القواعد:
- `save_section` يبني الإعداد الجديد بنسخة معدلة، يستدعي `validate_all` على **المجموع** (الأقسام + القوالب الحالية)، وإذا فشل ⇒ `Invalid` ولا يُكتب شيء. أقسام مقبولة: `identity|data_source|devices|web_subscribe|campaigns|app_check`، غيرها ⇒ `Invalid`.
- `expected_version` لا يطابق `app_configs.version` ⇒ `Conflict{current_version}`. نجاح ⇒ `version+1`.
- القوالب: `version` مستقل لكل قالب (يبدأ 1)، والتحقق يشمل قاعدة أن تغيير قالب لا يكسر الإعداد الكلي.
- كل كتابة داخل **معاملة** واحدة تشمل: الجدول الأساسي + صف `config_versions` (محتوى القسم/القالب JSON كامل) + صف `audit_log` (`action` مثل `config.save_section`، و`detail` يذكر القسم والإصدار **دون** أي سر؛ لا توجد أسرار في الإعدادات أصلاً). تحديث الذاكرة **بعد** نجاح الـ commit فقط.
- `restore`: يقرأ `config_versions.id` للتطبيق نفسه (وإلا `NotFound`)، يطبق محتواه كحفظ جديد عبر نفس مسار التحقق والإصدارات (لا يعدّل التاريخ).
- `export`: يرجع `ConfigDocument` JSON (مع `version:1` والقوالب)، وقابل لإعادة الاستيراد بدون فقد (اختبار round-trip).
- لا تخزّن شيئاً غير JSON الإعدادات. `secret_env` أسماء متغيرات فقط ولا يقرأها المخزن.

## 6. أوامر CLI (`src/cli.rs` + استدعاء في `main.rs`)
بلا مكتبة جديدة (`std::env::args`). **قبل** فحص CORS وقبل فتح المنفذ:
- `fcm_microservice import <app> <file.json>` ⇒ يقرأ الملف، `ConfigStore::import(..., actor="cli")`، يطبع `OK` أو قائمة `Issue` (سطر لكل خطأ: `path: message`) ويخرج بكود 0 أو 1.
- `fcm_microservice export <app>` ⇒ يطبع JSON منسقاً على stdout.
- بلا وسائط ⇒ السلوك الحالي دون تغيير. وسيط غير معروف ⇒ رسالة استخدام وكود 2.
الأوامران يستخدمان `DATABASE_URL` من `.env` كالمعتاد، ولا يتطلبان `credentials/` ولا `CORS_ALLOWED_ORIGINS`.
عند الإقلاع العادي أنشئ `Arc<ConfigStore>` وحمّله **وسجّل عدد التطبيقات** فقط (لا استخدام آخر)، وضعه في `AppState` كحقل `config`.
