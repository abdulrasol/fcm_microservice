## 1. الجدول (في `migrate`، بصيغة 3.14 حرفياً)
`devices(app, token, uid, platform, created_at, last_seen, PRIMARY KEY(app, token))` + `idx_devices_uid(app, uid)`. الترحيل idempotent (اختبر تشغيله مرتين).

## 2. `src/devices.rs` (واجهة داخلية)
```rust
pub struct DeviceStore { pool: SqlitePool, write_lock: tokio::sync::Mutex<()> }
impl DeviceStore {
    pub fn new(pool: SqlitePool) -> Self;
    /// Upserts (app, token) for `uid`. A token already owned by another uid moves to this uid.
    /// Enforces `max_per_uid` by deleting the least recently seen tokens of that uid. Returns the number of evicted rows.
    pub async fn register(&self, app:&str, uid:&str, token:&str, platform:Platform, max_per_uid:u32) -> Result<usize, DeviceError>;
    /// Removes the token only if it belongs to `uid`. Returns whether a row was removed.
    pub async fn unregister(&self, app:&str, uid:&str, token:&str) -> Result<bool, DeviceError>;
    pub async fn tokens_for_uid(&self, app:&str, uid:&str) -> Result<Vec<String>, DeviceError>;
    /// Bulk lookup for a list of uids (chunks of at most 50 bound parameters), de-duplicated, at most `cap` tokens.
    pub async fn tokens_for_uids(&self, app:&str, uids:&[String], cap:usize) -> Result<Vec<String>, DeviceError>;
    /// Removes a token FCM reported as dead (any owner). Returns whether a row was removed.
    pub async fn remove_dead_token(&self, app:&str, token:&str) -> Result<bool, DeviceError>;
}
pub enum Platform { Android, Ios, Web }   // serde lowercase; anything else is a 400
pub fn validate_token(token:&str) -> Result<(), String>; // 32..=4096 bytes, only [A-Za-z0-9:_\-.]
```
- `register`/eviction/transfer داخل **transaction واحدة** تحت `write_lock` (تفادي السباق عند تسجيلين متزامنين). المفتاح الأساسي يضمن token واحد لكل (app, token). `last_seen` يتحدث عند كل `register`.
- `max_per_uid` يُقصّ ضمن 1..=20 (القيمة خارج ذلك ⇒ تُقصّ، لا خطأ). الإخلاء يستثني الجهاز الذي سُجّل للتو.
- **لا تسجّل التوكن أبداً** (لا في `tracing` ولا في الأخطاء ولا في audit_log). مسموح تسجيل أول 6 أحرف فقط للتشخيص عند الحاجة.
- استعلامات SQL كلها بـbind؛ لا بناء نصي بقيم المستخدم. لبناء `IN (?, ?, ...)` استخدم `QueryBuilder` أو عدد علامات استفهام مولَّد فقط.

### أعضاء الدور (`tokens_for_role`)
في `devices.rs` أيضاً: `pub struct RoleDirectory` (مخبأ) مع
`pub async fn uids_for_role(&self, app:&str, version:i64, cfg:&RoleMembers, role_value:&str, source:&dyn DataSource) -> Result<Vec<String>, DeviceError>`:
- يتحقق من `role_value` (`^[A-Za-z0-9_\-]{1,64}$`) ثم `source.members(cfg.collection, cfg.field, role_value, cfg.max as usize)`؛ `DataError` ⇒ `DeviceError::Unavailable` (يصبح 503، fail closed).
- المخبأ بمفتاح `(app, version, role_value)` و TTL = `cfg.cache_seconds` (0 ⇒ بلا مخبأ)، حد 256 مدخلاً (امتلاء ⇒ نظّف المنتهي ثم امسح الكل)، لا يُخزَّن الخطأ، ولا يُمسَك القفل عبر `await`.
- ثم دالة مساعدة `DeviceStore::tokens_for_role(...)` تجمعها مع `tokens_for_uids` بسقف 5000 توكن.
- إن لم يكن `role_members` مضبوطاً في الإعداد ⇒ `DeviceError::NotConfigured` (يصبح 400 لاحقاً في T8/T9).

## 3. المسارات (في `main.rs`، تحت `/api/v1`)
- `POST /devices/register` جسم `{app, token, platform}` ، `POST /devices/unregister` جسم `{app, token}`. `#[serde(deny_unknown_fields)]`.
- المصادقة: ترويسة Bearer لهوية المستخدم عبر مزود التطبيق. لا مفتاح خدمة ولا مفتاح قديم هنا (الأجهزة تخص مستخدماً). ناقص/غير صالح ⇒ 401، مصدر المفاتيح غير متاح ⇒ 503، تطبيق مجهول (لا credentials) ⇒ 404 كما في `topics.rs`. فشل 401/403 يمر بـ`auth_fail_limiter` كما في بقية المسارات.
- حدود السرعة: IP عبر `topics::check_ip_limit` (الموجود) + حد جديد في `AppState`: `devices_limiter: RateLimiter` بـ **20 طلباً/دقيقة لكل uid** (المفتاح `uid:<app>:<uid>`). تجاوز ⇒ 429 عبر `topics::too_many_requests()`.
- `max_per_uid` من الإعداد (`config.get(app).config.devices.max_per_uid`)؛ تطبيق بلا إعداد ⇒ 5.
- الردود: register ⇒ `200 {"registered":true,"evicted":N}`؛ unregister ⇒ `200 {"removed":bool}` (لا تُميّز بين "غير موجود" و"ملك غيرك" كي لا يكون oracle: كلاهما `removed:false`). أخطاء التحقق ⇒ 400 برسالة عامة بلا تكرار التوكن.
- الجسم محدود بالطبقة الحالية (64KB). سجّل حدث `devices.register` فقط كعدّاد/`debug` بدون التوكن.

## 4. الاختبارات (بهذه الأسماء)

directory: `role_uids_cached_within_ttl`، `role_uids_zero_ttl_not_cached`، `role_uids_cache_invalidated_by_config_version`، `role_uids_source_error_is_unavailable_and_not_cached`، `role_value_validation_rejects_injection_like_input`، `role_cache_is_bounded`، `tokens_for_role_requires_role_members_config`.
