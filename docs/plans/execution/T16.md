## 1. المدير `CredentialManager` (في `credentials.rs`)
```rust
pub struct CredentialManager { dir: PathBuf, auth_map: AuthMap, project_map: ProjectIdMap, disabled: Arc<RwLock<HashSet<String>>>, verifier: Arc<dyn CredentialVerifier>, lock: tokio::sync::Mutex<()>, enabled: bool }
#[async_trait] pub trait CredentialVerifier: Send + Sync { async fn verify(&self, key:&ServiceAccountKey) -> Result<(), String>; }  // live check
pub struct GoogleVerifier;  // builds the authenticator and requests a token with scope firebase.messaging, 15 s timeout
pub struct ValidatedKey { pub app_project_id:String, pub client_email:String, pub private_key_id:String, key: ServiceAccountKey, raw: Vec<u8> }
```
- `parse_and_validate(bytes) -> Result<ValidatedKey, CredentialError>`: حجم ≤ 8192 بايت؛ JSON كائن؛ `type == "service_account"`؛ الحقول `project_id` و`client_email` و`private_key` و`private_key_id` نصوص غير فارغة؛ `project_id` `[a-z0-9-]{1,100}`؛ `client_email` ينتهي بـ`.gserviceaccount.com`؛ المفتاح الخاص يبدأ بـ`-----BEGIN PRIVATE KEY-----`؛ وبناء `ServiceAccountKey` يمر (PEM تالف ⇒ `CredentialError::Invalid("the private key could not be parsed")`). **لا تُضمَّن أي قيمة من الملف في رسائل الأخطاء.**
- `app_name_ok(app)`: `^[a-z0-9_-]{1,40}$` ولا يبدأ بنقطة/شرطة؛ يُفحص قبل أي عملية ملفات؛ المسار النهائي دائماً `dir.join(format!("{app}.json"))` بعد التحقق (واختبر أن `../x` و`a/b` و`.hidden` و`CON`-style تُرفض كلها).
- `install(app, bytes, replace:bool) -> Result<InstallOutcome, CredentialError>` تحت `lock` (عملية واحدة في كل مرة):
  1. `enabled` وإلا `CredentialError::Disabled`.
  2. `app_name_ok` ثم `parse_and_validate`.
  3. `replace=false` ⇒ الملف أو المفتاح في `project_map` موجود ⇒ `Exists`؛ `replace=true` ⇒ يجب أن يكون موجوداً، و`project_id` الجديد **يساوي** القديم (من `project_map`) وإلا `ProjectMismatch` (لا تذكر أسماء المشاريع في الرسالة العامة).
  4. `verifier.verify(&key)` ⇒ فشل ⇒ `LiveCheckFailed(<رسالة عامة>)` (سجّل التفصيل الآمن بدون أسرار).
  5. كتابة ذرية: ملف مؤقت في **نفس المجلد** باسم `.{app}.upload-{random}` (**لا ينتهي بـ`.json`** كي لا يلتقطه المراقب)، مفتوح بـ`create_new` وصلاحيات `0o600` من لحظة الإنشاء، `write_all` ثم `sync_all`، ثم `rename` إلى `{app}.json`، ثم `sync` للمجلد إن أمكن. أي فشل ⇒ حذف المؤقت.
  6. تحميل فوري: `load_credential(path, ...)` (لا تنتظر المراقب) وتحقق أن `project_map[app]` صار الجديد؛ فشل التحميل بعد الكتابة ⇒ أعد الملف القديم إن وُجد (احتفظ بنسخته في الذاكرة قبل الخطوة 5) أو احذف الجديد، ثم خطأ.
  7. يعيد `InstallOutcome{ client_email, private_key_id, project_id, replaced:Option<{client_email, private_key_id}> }` — **لا شيء من المفتاح**.
- `disable(app)`: يضيف للمجموعة `disabled` ويزيلها من `auth_map`/`project_map` فوراً (الإرسال يتوقف: كل مسار يرى التطبيق "غير موجود/بلا credentials"). `enable(app)`: يزيلها من المجموعة ويحمّل الملف. تُحفظ الحالة في جدول (الفقرة 2) وتُحمَّل عند الإقلاع **قبل** `scan_credentials_dir`، ويتجاهل `load_credential` أي تطبيق معطّل (حتى من المراقب).
- `remove(app)`: يحذف الملف (إن وُجد) ويزيل من الخرائط ومن مجموعة التعطيل.
- `metadata(app) -> Option<CredentialMeta{project_id, client_email, private_key_id}>`: يقرأ الملف ويستخرج هذه الحقول **فقط**.
- تعديلات على الموجود: `scan_credentials_dir` والمراقب يتجاهلان أي ملف اسمه يبدأ بنقطة؛ ويتجاهلان أسماء التطبيقات التي لا تحقق `app_name_ok` (تسجيل تحذير بالاسم فقط)؛ **لا تغيّر** سلوك الملفات الحالية الصالحة (مثل `watt.json`).
- `CREDENTIALS_DIR` (افتراضي `credentials`) و`CREDENTIALS_UPLOAD_ENABLED` (افتراضي `true`) يُقرآن في `main.rs` فقط؛ `enabled=false` ⇒ كل مسارات هذه الخطوة تجيب 404 (المسار موجود في الجدول لكن المعالج يرجع 404 مباشرة بعد `require_owner`، ليبقى اختبار المصفوفة سليماً).

## 2. قاعدة البيانات
جدولان (idempotent): `app_disabled(app TEXT PRIMARY KEY, disabled_by TEXT NOT NULL, disabled_at DATETIME DEFAULT CURRENT_TIMESTAMP)` و`app_credentials(app TEXT PRIMARY KEY, uploaded_by TEXT NOT NULL, uploaded_at DATETIME DEFAULT CURRENT_TIMESTAMP)` (لا أسرار؛ البريد وmeta من الملف). دوال بـbind.

## 3. المسارات (تحت `/api/v1/admin`، كلها `require_owner()` أولاً ثم `enabled` ثم المنطق؛ مسجلة في `admin_routes()`)
- `POST /apps` جسم `{app, service_account: <object>}` (`deny_unknown_fields`): `require_reauth(300)`؛ `install(replace=false)`؛ ثم `ConfigStore::create_app(app, actor)` (إن فشل إنشاء الإعداد بعد نجاح الملف ⇒ `remove(app)` وأعد الخطأ، لا تترك نصف تطبيق)؛ الرد `201 {app, project_id, client_email, private_key_id}`. تدقيق `app.create` (app, project_id, client_email — **بلا** private_key_id كاملاً؟ اسمح بـ`private_key_id` فقط فهو معرّف لا سر).
- `PUT /apps/{app}/credentials` جسم `{service_account}`: `require_reauth(300)`؛ `install(replace=true)`؛ الرد `{project_id, previous:{client_email, private_key_id}, current:{client_email, private_key_id}, reminder:"Revoke the old key in Google Cloud Console"}`. تدقيق `app.credentials.replace`.
- `GET /apps/{app}/credentials` ⇒ `metadata` + `uploaded_by/uploaded_at` إن وُجدا + `disabled`. لا يوجد أي مسار يعيد الملف.
- `POST /apps/{app}/disable` و`POST /apps/{app}/enable` (`require_reauth(300)` للتعطيل فقط). تدقيق.
- `DELETE /apps/{app}` جسم `{confirm}` يجب أن يساوي اسم التطبيق حرفياً (وإلا 400) + `require_reauth(300)`: ترتيب صارم: (1) `ConfigStore::export` وكتابته كاملاً في `audit_log` (`app.delete`, detail = JSON التصدير؛ لا أسرار فيه أصلاً) **قبل** أي حذف، وفشل التدقيق يوقف العملية؛ (2) `remove(app)`؛ (3) `ConfigStore::delete_app`؛ (4) حذف صفوف `devices` للتطبيق وإلغاء كل `app_keys` (revoke) وحذف `template_dedupe`؛ (5) تبقى `notifications_history` و`campaigns` و`audit_log` (وثّق). تطبيق غير موجود ⇒ 404.
- `GET /apps` و`GET /apps/{app}` (في `apps.rs`) يضيفان `disabled: bool`، و`has_credentials` يظل الحقيقة الفعلية للخريطة.
- كل أخطاء `CredentialError` ⇒ رموز: `Invalid`/`ProjectMismatch`/`LiveCheckFailed` ⇒ 400 برسالة عامة، `Exists` ⇒ 409، `NotFound` ⇒ 404، `Disabled` ⇒ 404، `Io` ⇒ 500 عامة.
- حدود: حجم الجسم ≤ 16KB تُفحص في المعالج (413 `payload too large`)؛ حد 10 عمليات/دقيقة لكل مستخدم (المحدد الموجود بمفتاح `admin:credentials:<id>`).

## 4. `ConfigStore::delete_app` (إضافة)
يحذف صف `app_configs` وكل `templates` للتطبيق في معاملة واحدة تحت قفل الكتابة، ويحدّث المخبأ، ويسجّل نسخة في `config_versions` (القسم `deleted`) وتدقيقاً. غير موجود ⇒ `NotFound`. اختبارات: `delete_app_removes_config_and_templates`، `delete_app_unknown_is_not_found`، `delete_app_is_atomic`.
