# T18 — عنوان العميل الحقيقي خلف Cloudflare + طلب /auth/me مرتين

## 1) عنوان IP للعميل (أمن)
**المشكلة:** `auth::client_ip` يأخذ **أول** عنصر من `X-Forwarded-For` عند `TRUST_PROXY=true`. عميل خبيث يرسل `X-Forwarded-For: <أي قيمة>` فتحفظها Cloudflare في المقدمة، فيتهرب من محدد محاولات الدخول (5/15 دقيقة) ومحددات المسارات العامة، أو يحرق حصة غيره.
الأداة تُخدَّم عبر Cloudflare Tunnel، وCloudflare تضع `CF-Connecting-IP` بقيمة العنوان الحقيقي ولا يمكن للعميل تزويرها عبر النفق.

**المطلوب (`src/auth.rs::client_ip` وملحقاته):**
- متغير بيئة جديد `CLIENT_IP_HEADER` (اختياري، الافتراضي فارغ). القيم المقبولة: `cf-connecting-ip` أو `x-real-ip` أو `x-forwarded-for` (اسم الترويسة بحروف صغيرة؛ قيمة غير معروفة ⇒ فشل الإقلاع برسالة واضحة).
- المنطق عند `TRUST_PROXY=true`:
  - إن حُدّد `CLIENT_IP_HEADER` ⇒ اقرأ هذه الترويسة فقط، وتحقق أنها عنوان IP صالح (`IpAddr::from_str`)؛ غير صالحة/مفقودة ⇒ ارجع إلى عنوان الـ peer (ولا تعتمد XFF).
  - إن لم يُحدَّد ⇒ السلوك الحالي لكن بدل **أول** عنصر من XFF خذ **آخر** عنصر (الذي أضافه البروكسي الموثوق) مع التحقق أنه IP صالح.
  - `TRUST_PROXY=false` ⇒ peer دائماً، تجاهل كل الترويسات.
- مرّر القيمة إلى كل مواضع `client_ip` الحالية (لا تغيّر التواقيع بلا داعٍ؛ ضعها في `AppState`/`AuthState`).
- اختبارات: كل حالة أعلاه + قيمة XFF مزوّرة `1.2.3.4, 9.9.9.9` + `CF-Connecting-IP` غير صالح + سلسلة طويلة جداً. **تجربة سلبية:** أعد سلوك "أول عنصر" مؤقتاً وأثبت فشل اختبار التزوير.
- حدّث: `.env.example`، `docs/deployment.md` (قسم TRUST_PROXY: مثال Cloudflare `CLIENT_IP_HEADER=cf-connecting-ip`)، `docs/release-checklist.md`، `docs.md` إن ذُكر المتغير، وجدول المتغيرات + `scripts/check_env_vars.sh` ينجح.

## 2) /auth/me ينادى مرتين في كل تحميل للوحة
**المشكلة:** `session.load()` ينفَّذ من الـ router guard ومن مكان ثانٍ (راجع `main.js`/`App.vue`/`router.js`)، فيظهر طلبان متتاليان في الشبكة.
**المطلوب:** حمّل مرة واحدة: احفظ الـ promise الجاري (`inflight`) وأعده للمنادين المتزامنين، و`session.loaded` يمنع إعادة التحميل ما لم يُطلب صراحة (بعد login/logout/reauth). اختبار vitest: استدعاءان متزامنان ⇒ طلب شبكة واحد؛ بعد `clear()` ثم `load()` ⇒ طلب جديد. أعد بناء `dist/` في commit منفصل.
