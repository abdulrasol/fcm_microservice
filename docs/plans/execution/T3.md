# الخطوة T3 — مزودات الهوية (Firebase + JWT عام) وسجلّها

**اقرأ أولاً:** `docs/plans/execution/RULES.md`، ثم من `docs/plans/secure-sending-plan.md`: القسم 3.3 (مزودات الهوية) والمهمة T3.
**الفرع:** `feature/policy-auth` (تحقق منه قبل البدء وقبل كل commit). الملف `T3.md` غير متعقب وهذا متوقع.
**قاعدة اللغة (مستمرة):** كل ما في `src/` بالإنجليزية فقط (تعليقات، أخطاء، سجلات، أسماء اختبارات). فحص القبول المعدّل: `grep -rnP '[\x{0600}-\x{06FF}]' src --exclude=validation.rs --exclude=topics.rs` ⇒ صفر (الملفان يحتويان بيانات اختبار عربية مقصودة وتبقيان كما هما).
**الهدف:** فصل "من هو المستخدم" خلف واجهة موحدة، وإضافة مزود JWT عام (Supabase / Auth0 / Keycloak / باك إند خاص) بجانب Firebase، وسجل يختار المزود لكل تطبيق من إعداداته. **لا تربط السجل بمسارات الإرسال بعد** (هذا في T5/T8). سلوك كل المسارات الحالية يبقى كما هو بايت-ببايت.

## 1. إصلاح صغير مؤجل من T2 (commit مستقل أول)
`ConfigStore::import` يعيد إصدار كل قالب إلى 1. اجعله **متصاعداً**: لقالب موجود يكون `إصداره القديم + 1`، وللجديد 1، وللقوالب المحذوفة بالاستيراد يبقى تاريخها في `config_versions`. الاختبار: `import_keeps_template_versions_monotonic` (استورد مرتين وتحقق أن إصدار نفس القالب 1 ثم 2 وأن عميلاً يحمل `expected_version=1` يحصل على `Conflict`).
الرسالة: `fix(config): T3-0 keep template versions monotonic across import`.

## 2. إعادة الهيكلة بلا تغيير سلوك (commit مستقل ثانٍ)
في `auth.rs` الآن يوجد منطق تحقق Firebase ID token مع كاش JWKS (`JwkProvider`، `FetchedJwks`، `GoogleJwkProvider`، `JwkCache`، `decoding_key`، `refresh_keys`، `RawClaims`/`VerifiedClaims`، و`verify_id_token`).
- **انقل (لا تعد كتابة)** المكونات العامة إلى `identity/jwks.rs`: trait `JwkProvider` و`FetchedJwks` و`JwksCache` (الكاش وسياسة التحديث: `Cache-Control: max-age` بين 60ث و6س، ومفتاح مجهول ⇒ تحديث واحد كحد أقصى كل 60ث، وفشل التحديث بعد انتهاء الصلاحية ⇒ `Unavailable`) وعميل `HttpJwkProvider::new(client, url)` (يعمّم `GoogleJwkProvider`؛ أبقِ `GoogleJwkProvider::new(client)` كمُنشئ يمرّر عنوان Google).
- وانقل منطق التحقق الخاص بـ Firebase إلى `identity/firebase.rs` كـ `FirebaseVerifier`.
- يبقى `AuthService` بنفس **واجهته العامة وتواقيعه** (مُنشئه `AuthService::new(project_map, jwks, firestore, config)` وكل دواله العامة)، ويستدعي المكونات المنقولة داخلياً. أعد تصدير الأسماء التي يستعملها `main.rs` والاختبارات (`pub use`) بحيث لا يتغير نص أي اختبار.
- **قاعدة صارمة:** كل اختبارات `auth.rs` الحالية تمر بلا تعديل في أي `assert`. يُسمح فقط بتغيير مسارات `use`/الاستيراد داخل وحدة الاختبار إذا لزم.
- أنقل اختبارات الكاش الخاصة بالمفاتيح إلى مكانها الجديد إن كانت منفصلة، وإلا اتركها.
الرسالة: `refactor(identity): T3-1 extract JWKS cache and Firebase verifier from auth.rs`. بعد هذا الـ commit: `cargo test` يعطي نفس عدد الاختبارات القديمة + الجديدة، كلها ناجحة، و`git diff` لـ`auth.rs` ينقص أسطراً أكثر مما يضيف.

## 3. الواجهة والمزودات (commit ثالث)
### `identity/mod.rs`
```rust
pub struct Identity { pub uid: String, pub email: Option<String>, pub name: Option<String>, pub claims: serde_json::Value }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum IdentityError { Invalid(&'static str) /* maps to 401 */, Unavailable(String) /* 503 */ }
#[async_trait] pub trait IdentityProvider: Send + Sync { async fn verify(&self, token: &str) -> Result<Identity, IdentityError>; }
pub fn claim_at<'a>(claims: &'a Value, path: &str) -> Option<&'a Value>; // dotted path, objects only
```
- `claim_at`: يفصل بنقاط، ويرفض المقاطع الفارغة، ويرجع أي نوع Value (يحتاجه T5 لقراءة أدوار من مصفوفة مثل `realm_access.roles`).
- تحويل uid: نص غير فارغ ≤128 حرفاً بلا أحرف تحكم؛ عدد صحيح يُحوَّل لنص؛ أي نوع آخر ⇒ `Invalid("token has no usable uid")`.

### `identity/firebase.rs`
`FirebaseProvider { project_id, verifier }` ينفّذ `IdentityProvider` بنفس القواعد الحالية حرفياً (RS256، issuer/audience، `auth_time`، `exp`…) ويرجع `Identity` (uid + email من التوكن). الكاش مشترك بين كل تطبيقات Firebase (نسخة واحدة من `JwksCache` لعنوان Google).

### `identity/jwt.rs`
`JwtProvider::new(config: &JwtProviderConfig, env: Arc<dyn EnvSource>, jwks: Arc<dyn JwkProvider>)` حيث `EnvSource` trait صغير (`fn get(&self, name:&str)->Option<String>`) له تنفيذ للبيئة الحقيقية وتنفيذ وهمي للاختبارات (لا تعدّل `std::env` في الاختبارات).
قواعد `verify`:
1. الطول ≤ 8192، وإلا `Invalid`.
2. اقرأ ترويسة التوكن؛ `alg` يجب أن يكون ضمن `algorithms` المضبوطة **حرفياً**. `none` أو غير المدعوم ⇒ `Invalid`. **لا تأخذ المفتاح أبداً من ترويسة التوكن** (`jwk`/`jku`/`x5u` تُتجاهل).
3. العائلة تحدد المفتاح: RS256/ES256 ⇒ من JWKS (`kid` إلزامي إلا إذا كانت المجموعة فيها مفتاح واحد فقط، فيُستعمل هو)، والـ `kid` ≤ 128. HS256 ⇒ السر من `env.get(hs256_secret_env)`؛ غير موجود أو أقصر من 32 بايت ⇒ `Unavailable("identity secret is not configured")` وسجّل `tracing::error!` يذكر **اسم المتغير فقط**. لا خلط عائلات: توكن HS256 على مزود RS256 ⇒ `Invalid`، والعكس كذلك.
4. التحقق: التوقيع، `exp` إلزامي، `iss == issuer`، `aud` (نص يساوي أو مصفوفة تحتوي)، `nbf` إن وجد (سماحية 60ث)، `iat` إن وُجد: لا يتجاوز الآن+60ث ولا يقدم عن الآن بأكثر من `max_age_seconds`. `sub`/`uid_claim` عبر `claim_at` ثم قواعد تحويل uid أعلاه.
5. `email` من claim `email` (نص) إن وُجد، و`name` من `name_claim` إن ضُبط.
6. مفتاح مجهول ⇒ سلوك الكاش (تحديث واحد/دقيقة). فشل جلب JWKS ⇒ `Unavailable`.
7. عميل JWKS: `HttpJwkProvider` يُنشأ بعميل `reqwest` مخصص: مهلة 5ث، **بدون إعادة توجيه** (`redirect::Policy::none()`)، حد حجم الرد 64KB، ويرفض عناوين غير `https://` وقت التشغيل أيضاً.
8. لا تسجّل التوكن ولا مفتاح HS256 ولا محتوى claims في أي سجل.

### `identity/registry.rs`
`IdentityRegistry::new(config: Arc<ConfigStore>, project_map: ProjectIdMap, client: reqwest::Client, env: Arc<dyn EnvSource>)` و:
`pub async fn provider_for(&self, app: &str) -> Result<Arc<dyn IdentityProvider>, IdentityError>`
- للتطبيق إعداد في المخزن: ابنِ المزود من `config.identity.provider` (firebase ⇒ يحتاج `project_id` من `project_map`؛ غير موجود ⇒ `Unavailable("app has no loaded credentials")`).
- مخبأ لكل `(app, config.version)`؛ تغيّر النسخة ⇒ إعادة بناء. لا تبنِ من الصفر عند كل طلب.
- تطبيق بلا إعداد في المخزن لكن له credentials ⇒ مزود Firebase الافتراضي مع `tracing::warn!` مرة واحدة لكل تطبيق ("no configuration, falling back to the default Firebase provider").
- تطبيق مجهول تماماً ⇒ `Invalid("unknown app")`.
أضف `identity: Arc<IdentityRegistry>` إلى `AppState` مع `#[allow(dead_code)]` وتعليق إنجليزي ("wired in T5/T8").

## 4. الاختبارات المطلوبة (بهذه الأسماء)
- مرحلة 1: `import_keeps_template_versions_monotonic`.
- مرحلة 2: كل اختبارات `auth.rs` القديمة بلا تغيير.
- claims: `claim_path_reads_nested_and_arrays`، `claim_path_rejects_empty_segments`، `uid_conversion_rules`.
- firebase: `firebase_provider_returns_identity_with_email`، `firebase_provider_rejects_wrong_audience`.
- jwt (مفاتيح RS256 تُولَّد في الاختبار كما تفعل اختبارات auth الحالية): `jwt_rs256_valid_token_accepted`، `jwt_audience_array_accepted`، `jwt_wrong_issuer_rejected`، `jwt_wrong_audience_rejected`، `jwt_expired_rejected`، `jwt_future_iat_rejected`، `jwt_older_than_max_age_rejected`، `jwt_alg_none_rejected`، `jwt_hs256_token_against_rs256_provider_rejected`، `jwt_rs256_token_against_hs256_provider_rejected`، `jwt_hs256_valid_accepted`، `jwt_hs256_missing_secret_env_is_unavailable`، `jwt_short_hs256_secret_is_unavailable`، `jwt_nested_uid_claim`، `jwt_numeric_uid_claim_converted`، `jwt_missing_uid_claim_rejected`، `jwt_uid_too_long_rejected`، `jwt_oversized_token_rejected`، `jwt_unknown_kid_refreshes_once_per_minute`، `jwt_missing_kid_uses_sole_key`، `jwt_jwks_fetch_failure_is_unavailable`، `jwt_header_supplied_key_is_ignored` (توكن بترويسة `jwk` لمفتاح المهاجم موقَّع به ⇒ مرفوض).
- registry: `registry_builds_provider_per_config`، `registry_rebuilds_when_config_version_changes`، `registry_caches_provider_between_calls`، `registry_defaults_to_firebase_without_config`، `registry_firebase_without_credentials_is_unavailable`، `registry_unknown_app_is_invalid`.
ES256: اجعل الدعم يُترجَم، لكن إذا لم تتوفر طريقة توليد مفاتيح اختبار بلا اعتماديات جديدة فلا تكتب له اختباراً، واذكر ذلك صراحةً في التقرير كـ"غير مغطى".
