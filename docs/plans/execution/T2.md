# الجزء 0 — إصلاح ما وجدته المراجعة في T1 (commit مستقل أول)

حكمي على T1: مقبول من حيث النطاق والجودة، وقواعدك الإضافية ([T0] وغيرها) **موافَق عليها**. لكن الكود فيه الأخطاء التالية يجب إصلاحها قبل البناء فوقه. لا تغيّر شيئاً آخر.

**F1 — تسابق الكتابات في `ConfigStore` (خطأ حقيقي).** كل دالة كتابة تقرأ `snapshot` ثم تتحقق ثم تكتب ثم `update_cache` بالنسخة القديمة:
- `save_template` ينتهي بـ `update_cache(.., snapshot.config.clone(), templates, snapshot.version)` فإذا نجح `save_section` بالتوازي يرجع الكاش إلى إعداد قديم (القاعدة جديدة والذاكرة قديمة).
- حفظ قالبين بالتوازي: كلاهما ينسخ `snapshot.templates` ويضيف قالبه فقط، فيمسح الأخير قالب الأول من الكاش (وهو في القاعدة).
- التحقق قد يجري على لقطة قديمة فتُكتب حالة لم يتحقق منها أحد.
الإصلاح: أضف إلى `ConfigStore` حقل `write_lock: tokio::sync::Mutex<()>`، وكل الدوال التي تعدّل (`create_app`, `save_section`, `save_template`, `set_template_enabled`, `delete_template`, `restore`, `import`) تأخذ القفل **في أول سطر** وتبقيه حتى بعد `update_cache`، وتقرأ `snapshot` **بعد** أخذ القفل. (`restore` الذي يستدعي `save_*` داخلياً: أعد هيكلة الدوال الداخلية `*_locked` بحيث لا يُؤخذ القفل مرتين → deadlock.) افتراض النسخة الواحدة (single instance) يُذكر في تعليق أعلى `store.rs`.
قرار على سؤالك المفتوح: **حفظ قالب لا يرفع `app_configs.version`** (النسخة تخص الإعدادات العامة فقط، وتعارض القوالب يُكتشف بـ `expected_version` الخاص بكل قالب). لا تغيّر ذلك. اكتب القرار في تعليق على `AppSnapshot::version`.
فحص `expected_version` الخاص بالقالب ينفَّذ **تحت القفل** (لم يعد فيه TOCTOU).

**F2 — فقدان `last_used_at`، و`updated_at` لا يتحدث.**
- `save_template` يستخدم `INSERT OR REPLACE` فيعيد `last_used_at` إلى NULL (T10 يعتمد عليه لمنع حذف قالب مستخدم). استبدله بـ `INSERT ... ON CONFLICT(app, key) DO UPDATE SET definition=excluded.definition, enabled=excluded.enabled, version=excluded.version, updated_by=excluded.updated_by, updated_at=CURRENT_TIMESTAMP` (لا يلمس `last_used_at`).
- `UPDATE app_configs` في `write_config` لا يحدّث `updated_at`: أضف `updated_at = CURRENT_TIMESTAMP`. وكذلك أي تحديث آخر في `set_template_enabled`.
- `import`: لا بأس بـ `INSERT OR REPLACE` على `app_configs`، لكن **لا** على `templates` (احذف قوالب غير موجودة في المستند، وحدّث الباقي بنفس الـ UPSERT).

**F3 — حاجز [G6] جديد.** قالب غير الأدمن هدفه `to.role` يجب أن يكون الدور **حرفياً** وأحد `identity.admin_roles` (وإلا يستطيع غير الأدمن بث نص إلى كل مستخدمي دور عادي). الرسالة: `"[G6] a non-admin template may only target an admin role"`. يُضاف في `validate_non_admin_guards`.

**F4 — ترجمة التعليقات العربية الموجودة إلى الإنجليزية** في: `src/config/*.rs`، `src/cli.rs`، وما أضفته أنت في `src/db.rs` و`src/main.rs` (مثل تعليق `-- JSON بلا templates` و`/// T1: مخزن الإعدادات...`). ترجمة المعنى لا الحرف. لا تغيّر أي منطق في هذه الخطوة الفرعية.

**الاختبارات الجديدة للجزء 0 (بهذه الأسماء):**
`concurrent_template_saves_keep_all_templates_in_cache`، `concurrent_section_and_template_saves_leave_cache_equal_to_db`، `template_save_preserves_last_used_at`، `save_section_refreshes_updated_at`، `import_removes_templates_missing_from_document`، `g6_non_admin_role_target_must_be_admin_role`، `g6_admin_role_target_allowed`.
- اختبارات التزامن: `Arc<ConfigStore>` و`tokio::spawn` لـ 8 مهام على الأقل، ثم قارن الكاش مع ما في القاعدة (أعد بناء `ConfigStore::new` على نفس الـ pool وقارن اللقطتين بالتساوي). الاختبار الذي يمر بدون القفل لا قيمة له: تأكد (مرة واحدة، يدوياً، ولا تُبقِ ذلك في الكود) أن الاختبار الأول **يفشل** عند تعطيل القفل مؤقتاً، وسجّل ذلك في التقرير.
- `template_save_preserves_last_used_at`: اضبط `last_used_at` بـ SQL مباشر ثم احفظ القالب مجدداً.

**commit الجزء 0:** `fix(config): T2-0 serialize config writes, keep last_used_at, add G6, English comments` ثم تأكد أن كل اختبارات T1 ما زالت ناجحة.

# الجزء 1 — T2: حسابات الداشبورد والجلسات

**الهدف:** نظام دخول للداشبورد مستقل عن Firebase: حسابات `owner` / `manager`، جلسات cookie، تغيير كلمة المرور، إعادة التأكيد (reauth)، وأمرا CLI لإنشاء المالك واستعادته. **لا واجهات إدارة تطبيقات/قوالب بعد** (هذه T10). ولا تعدّل `dashboard/` (T12).

## 1. التعديلات المسموحة
- جديد: `src/admin/mod.rs` (الـ Router وتجميع المسارات)، `src/admin/auth.rs` (المنطق والـ extractor)، `src/admin/password.rs` (argon2 وسياسة كلمة المرور)، `src/admin/session.rs` (التوكن والكوكي).
- تعديل: `src/db.rs` (جداول جديدة)، `src/main.rs` (`mod admin`، تركيب المسار، حقول `AppState`)، `src/cli.rs` (أمران)، `Cargo.toml`، `.env.example`.
- `Cargo.toml`: أضف في `[dependencies]`: `argon2 = "0.5"`، وانقل `rand = "0.8"` و`base64 = "0.22"` من `[dev-dependencies]` إلى `[dependencies]` (لا تكررهما)، وأضف في `[dev-dependencies]`: `tower = { version = "0.4", features = ["util"] }` و`http-body-util = "0.1"`. لا شيء غير ذلك.
- ممنوع: `src/auth.rs` و`topics.rs` و`validation.rs` و`credentials.rs` و`dashboard/`.
- إذا أضفت `pub` لدالة قديمة (مثل `client_ip` وهي `pub` أصلاً) فلا بأس، لكن لا تعدّل جسمها.

## 2. الجداول (في `db::migrate`)
```sql
CREATE TABLE IF NOT EXISTS tool_users (
  id INTEGER PRIMARY KEY AUTOINCREMENT, email TEXT NOT NULL UNIQUE COLLATE NOCASE,
  password_hash TEXT NOT NULL, role TEXT NOT NULL CHECK (role IN ('owner','manager')),
  must_change_password INTEGER NOT NULL DEFAULT 1, test_uid TEXT,
  disabled INTEGER NOT NULL DEFAULT 0, created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE IF NOT EXISTS tool_user_apps (
  user_id INTEGER NOT NULL REFERENCES tool_users(id) ON DELETE CASCADE, app TEXT NOT NULL,
  PRIMARY KEY (user_id, app)
);
CREATE TABLE IF NOT EXISTS tool_sessions (
  id_hash TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES tool_users(id) ON DELETE CASCADE,
  expires_at DATETIME NOT NULL, reauth_at DATETIME, created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  ip TEXT, user_agent TEXT
);
CREATE INDEX IF NOT EXISTS idx_tool_sessions_user ON tool_sessions(user_id);
```
فعّل `PRAGMA foreign_keys = ON` لكل اتصال في `init_db` (عبر `SqliteConnectOptions::foreign_keys(true)` أو `after_connect`) **وفي أداة اختبارات الذاكرة**، واختبر أن حذف مستخدم يحذف جلساته.
أوقات الصفوف تُخزَّن بتنسيق ثابت UTC (`strftime('%Y-%m-%d %H:%M:%S','now')`) أو epoch seconds كـ INTEGER، واختر واحداً وطبّقه بثبات (يُفضّل INTEGER epoch لأنه يتجنب أخطاء مقارنة النصوص). إذا اخترت INTEGER فغيّر أنواع الأعمدة أعلاه وسجّل ذلك كانحراف مبرَّر.

## 3. كلمات المرور (`password.rs`)
- `argon2id` عبر crate `argon2` بالمعاملات الافتراضية (`Argon2::default()`، أي m=19 MiB, t=2, p=1)، والملح من `OsRng`، والتخزين بصيغة PHC string.
- التجزئة والتحقق يعملان في `tokio::task::spawn_blocking` (عملية ثقيلة).
- السياسة: الطول 12..=128 حرفاً، لا تساوي البريد ولا جزءه المحلي (قبل `@`)، وليست من قائمة ثابتة صغيرة (حوالي 20) من كلمات السر الشائعة داخل الكود (مثل `password1234` و`123456789012`). لا مكتبات إضافية.
- `verify_or_dummy(hash: Option<&str>, password)`: إذا المستخدم غير موجود تحقق مقابل hash وهمي ثابت (يُولَّد مرة عند الإقلاع) لتتساوى المدة التقريبية للرد (منع تعداد الحسابات بالتوقيت).

## 4. الجلسات (`session.rs`)
- المعرّف: 32 بايت عشوائية من `OsRng`، بترميز base64url بلا padding. **يُخزَّن SHA-256 hex فقط** (`id_hash`)، والمعرّف الخام لا يُسجَّل أبداً.
- الصلاحية: 12 ساعة مطلقة (ثابت قابل للتعديل بـ `ADMIN_SESSION_HOURS`، افتراضي 12، حدّه الأعلى 72).
- حد 10 جلسات للمستخدم: عند إنشاء الحادية عشرة تُحذف الأقدم.
- تنظيف الجلسات المنتهية: عند كل تسجيل دخول، ومهمة `tokio::spawn` كل ساعة (وتتوقف مع العملية).
- الكوكي: الاسم `__Host-fcm_session` عندما `COOKIE_SECURE` مفعّل (الافتراضي `true`)، وإلا `fcm_session`. الخصائص: `HttpOnly; SameSite=Strict; Path=/` و`Secure` عند التفعيل، و`Max-Age` = مدة الجلسة. **لا Domain.** يُحذف عند الخروج بـ `Max-Age=0`.
- لا مكتبة cookie: اكتب تحليلاً صغيراً لترويسة `Cookie` وتركيباً لـ `Set-Cookie` يدوياً مع اختبارات (قيمة بها `;` أو مسافات، ترويسات متعددة).
- أضف `COOKIE_SECURE` و`ADMIN_SESSION_HOURS` إلى `.env.example` مع شرح بالإنجليزية.

## 5. الواجهات (JSON، تحت `/api/v1/admin`)
أخطاء هذا الـ Router بصيغة JSON موحدة `{"error":"<code>","message":"<text>"}` (ليس نصاً عادياً كبقية الأداة)، والأكواد: `unauthorized`، `forbidden`، `password_change_required`، `invalid_request`، `rate_limited`.

| الطريقة والمسار | الجسم | الرد |
|---|---|---|
| `POST /auth/login` | `{email, password}` | `200 {user}` + `Set-Cookie`. أي فشل (بريد غير موجود، كلمة خاطئة، حساب معطل) ⇒ `401 unauthorized` برسالة **واحدة** متطابقة |
| `POST /auth/logout` | — | `204` + حذف الكوكي (يعمل حتى بجلسة منتهية) |
| `GET /auth/me` | — | `200 {id, email, role, apps:[...], must_change_password}` |
| `POST /auth/password` | `{current_password, new_password}` | `204`، يصفّر `must_change_password`، ويحذف **كل الجلسات الأخرى** للمستخدم (يبقي الحالية) |
| `POST /auth/reauth` | `{password}` | `204` ويضبط `tool_sessions.reauth_at = now` |

- `user` في الرد: `{id, email, role, apps, must_change_password}` — **لا** `password_hash` ولا `test_uid` ولا أي حقل آخر.
- أضف الـ Router داخل `api_routes` الحالي بـ `.nest("/admin", admin::router())` بحيث يرث `RequestBodyLimitLayer` (64KB) ويمر `api_fallback` لغير المعروف. الحالة المشتركة `Arc<AppState>` فيها حقل جديد `tool_auth: Arc<ToolAuth>` (يحمل pool وإعدادات الكوكي والمحدّدات).
- **حماية CSRF:** أي طلب غير `GET/HEAD/OPTIONS` ⇒ يجب أن تكون ترويسة `X-Requested-With` موجودة وقيمتها `fcm-dashboard` تماماً، وإلا `403 forbidden`. وإذا وُجدت ترويسة `Origin` فيجب أن تساوي `scheme://Host` للطلب أو أحد `CORS_ALLOWED_ORIGINS`، وإلا `403`. (يسري على `login` أيضاً.)
- **`must_change_password`:** طالما `true` تُرفض كل المسارات بـ `403 password_change_required` ما عدا `GET /auth/me` و`POST /auth/password` و`POST /auth/logout`.
- **extractor:** نفّذ `AuthedUser` كـ `FromRequestParts<Arc<AppState>>` يقرأ الكوكي، يتحقق من الجلسة (صلاحية، المستخدم غير معطل)، ويرجع `{ user_id, email, role, apps, must_change_password, session_id_hash, reauth_at }`. وأضف دوال مساعدة قابلة لإعادة الاستخدام في T10 (لا تربطها بمسارات الآن، لكن اختبرها):
  - `fn require_owner(&self) -> Result<(), AdminError>`
  - `fn require_app(&self, app: &str) -> Result<(), AdminError>` (owner: دائماً، manager: فقط إن كان `app` ضمن `tool_user_apps`، وإلا 403)
  - `fn require_reauth(&self, max_age_secs: i64) -> Result<(), AdminError>` (403 `forbidden` برسالة `reauth_required` إذا `reauth_at` فارغ أو أقدم).
- **حدود المحاولات** (باستخدام `RateLimiter` الموجود دون تعديله): فشل الدخول يُحصى لكل بريد (بعد تحويله إلى lower-case) ولكل IP: 5 محاولات فاشلة/15 دقيقة. المحاولة السادسة ⇒ `429 rate_limited` **بدون** فحص كلمة المرور. ملاحظة: `RateLimiter::check` يسجّل ضربة عند كل استدعاء، لذلك استدعِه **عند الفشل فقط** (بعد التحقق) واستخدم `check` بعد ذلك لقراءة الحالة؛ إذا لم تكفِ الواجهة فأضف طريقة عامة صغيرة `is_blocked(key)` في `ratelimit.rs` (تعديل مسموح ومحدود لهذا الملف فقط، وبلا تغيير سلوك الدوال الحالية، واختبرها). نجاح الدخول لا يصفّر العداد.
- `ip` و`user_agent` في الجلسة: `client_ip(headers, peer, trust_proxy)` الموجودة، و`User-Agent` مقصوصاً إلى 200 حرف.
- **تدقيق:** صف في `audit_log` لكل: دخول ناجح (`admin.login`)، دخول فاشل (`admin.login_failed`، والـ detail يذكر **hash قصير للبريد** أو البريد المنقّح لا كلمة المرور، ولا تكتب بريداً غير موجود حرفياً — اكتب `unknown_email`)، خروج، تغيير كلمة، reauth.

## 6. CLI (في `src/cli.rs`)
- `fcm_microservice create-owner --email <email>`: ينشئ مالكاً بكلمة مرور مؤقتة عشوائية (20 حرفاً من أبجدية بلا حروف ملتبسة `0O1lI`)، `must_change_password=1`، ويطبعها **مرة واحدة** على stdout بسطر `TEMP_PASSWORD=...`. البريد موجود ⇒ خروج بكود 1 دون تعديل. سجّل `audit_log` بـ `actor="cli"`.
- `fcm_microservice reset-owner-password --email <email>`: للاستعادة، يولّد كلمة مؤقتة جديدة، يضبط `must_change_password=1`، **يحذف كل جلسات المستخدم**، ويطبعها. غير مالك أو غير موجود ⇒ كود 1.
- صيغة البريد: تحقق بسيط (وجود `@` ونقطة بعده، ≤ 254، بلا مسافات) ثم lower-case قبل التخزين.
- **أمني:** لا تطبع كلمة المرور المؤقتة في أي مكان غير stdout هذين الأمرين، ولا تدخلها في أي سجل tracing.
