## 2. جدول المفاتيح (في `migrate`، idempotent)
```sql
CREATE TABLE IF NOT EXISTS app_keys (
  id INTEGER PRIMARY KEY AUTOINCREMENT, app TEXT NOT NULL, name TEXT NOT NULL,
  key_hash TEXT UNIQUE NOT NULL, hint TEXT NOT NULL, created_by TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP, last_used_at DATETIME, revoked_at DATETIME
);
CREATE INDEX IF NOT EXISTS idx_app_keys_app ON app_keys(app);
```
(`hint` = آخر 4 أحرف من المفتاح لعرضها في القائمة؛ هذا الإضافة الوحيدة على صيغة 3.14 وتُوثَّق في الخطة.)

## 3. `src/appkeys.rs`
- صيغة المفتاح: `fcm_<app>_<R>` حيث `R` = 32 بايتاً عشوائياً بـbase64url بلا حشو (43 حرفاً)، من مولد آمن (نفس مصدر `session::generate_token`، لا `rand::thread_rng` عادي إن كان غير تشفيري). `app` يطابق `[a-z0-9_-]{1,40}`.
- `pub struct AppKeyStore { pool, last_touch: Mutex<HashMap<i64, Instant>> }`:
  - `create(app, name, created_by) -> Result<NewKey{id, key}, KeyError>`: `name` 1..=60 بلا أحرف تحكم؛ حد 20 مفتاحاً **غير ملغى** لكل تطبيق (`KeyError::TooMany`)؛ يخزّن `sha256` hex فقط و`hint`.
  - `list(app) -> Vec<KeyInfo{id, name, hint, created_by, created_at, last_used_at, revoked_at}>` (لا hash).
  - `revoke(app, id) -> Result<bool>`: `UPDATE ... SET revoked_at=CURRENT_TIMESTAMP WHERE id=? AND app=? AND revoked_at IS NULL`؛ `false` ⇒ 404.
  - `check(token:&str, request_app:&str) -> KeyCheck`: ينتهي بأحد: `NotAKey` (لا يبدأ بـ`fcm_`)، `Valid{id}`، `WrongApp` (المفتاح صالح لكن لتطبيق آخر ⇒ 403)، `Invalid` (شكل مفتاح لكنه غير موجود أو ملغى أو مشوّه ⇒ 401).
    خطوات: تحقق الشكل (البادئة، طول الجزء العشوائي 43 وأحرف base64url)؛ استخرج `app` من الوسط **بقطع آخر 44 حرفاً (`_` + 43)** (لأن اسم التطبيق قد يحتوي `_`)؛ احسب hash المفتاح كاملاً وابحث بالفهرس الفريد؛ مفتاح ملغى ⇒ `Invalid` (نفس رد غير الموجود)؛ مقارنة `row.app == request_app` ثم الجزء المضمّن في المفتاح `== row.app` (دفاع إضافي)؛ فشل المطابقة ⇒ `WrongApp`.
  - تحديث `last_used_at` على الاستعمال الناجح مع **خنق**: على الأكثر مرة كل 60 ثانية لكل مفتاح (في الذاكرة، حد 10 آلاف مدخل ثم تنظيف)، والكتابة لا تفشل الطلب (`let _`).
  - **لا مخبأ للصلاحية**: كل `check` يقرأ الجدول (الإلغاء فوري).
- لا يُسجَّل المفتاح ولا hash في `tracing` ولا `audit_log` ولا الأخطاء؛ يجوز تسجيل `id` فقط.

## 4. الربط بالمسارات الحية
مرِّر الفحص عبر دالة واحدة في `main.rs`/`auth.rs`: `trusted_sender(state, headers, app) -> Result<Option<TrustedSender>, (StatusCode,String)>` تقرأ Bearer ثم:
1. تساوي `SERVICE_API_KEY` ⇒ `Some(Service)` (كما اليوم).
2. تبدأ بـ`fcm_` ⇒ `appkeys.check`: `Valid` ⇒ `Some(AppKey{id})`؛ `WrongApp` ⇒ **403** `Forbidden`؛ `Invalid` ⇒ **401** مع احتساب فشل مصادقة على `auth_fail_limiter` (IP) كما في `auth_error_with_limit`.
3. غير ذلك ⇒ `None` (يتابع الفحص كهوية مستخدم كما اليوم).
مواضع التطبيق (ابحث عن كل `verify_service_key` في `main.rs`/`auth.rs` وصنّفها في التقرير): 
- **تقبل مفتاح التطبيق** (تطبيق محدد في الطلب): `POST /send` (المرسل `AdminIdentity{uid:"key:<id>"}`)، `POST /send/template` (المرسل `Sender{uid:"key:<id>", role:None}` مثل service: يتخطى `senders` وحد uid)، `POST /campaigns` و`GET /campaigns` و`POST /campaigns/{id}/cancel` (مثل service: بلا مراجعة)، و`POST /topics/subscribe|unsubscribe` (مستوى Admin للتطبيق نفسه).
- **تبقى للمفتاح العام فقط:** أي مسار بلا `app` (مثل `GET /apps` القديم، `authenticate_admin_any`)، و`/history`، و`/topics` الإداريتان القديمتان، ما لم تجد أن قبول المفتاح فيهما آمن وضروري — لا توسّع النطاق؛ سجّل القرار.
- المفتاح القديم `API_KEY` يبقى `/send` فقط كما هو؛ ومفتاح التطبيق **لا** يُقبل في أي مسار `/admin/*` ولا `/devices/*`.
- `require` في القوالب التي تعتمد `{sender.uid}`: المفتاح uid = `key:<id>` فيرد 403؛ كما قرر المراجع لمفتاح الخدمة، ويوثَّق في T13.
- تحذير الإقلاع: إن كان `SERVICE_API_KEY` معرّفاً ⇒ `tracing::warn!("SERVICE_API_KEY is set; prefer per-app keys")` مرة واحدة.

## 5. واجهات الداشبورد (`src/admin/keys.rs`، owner فقط، كل معالج يبدأ بـ`user.require_owner()`)
- `GET /apps/{app}/keys` ⇒ قائمة `KeyInfo` (الإلغاءات تظهر بـ`revoked_at`).
- `POST /apps/{app}/keys` جسم `{name}` (`deny_unknown_fields`): تطبيق موجود (إعداد أو credentials) وإلا 404؛ `require_reauth(300)`؛ حد 20 ⇒ 409؛ الرد `201 {id, name, key}` مع `Cache-Control: no-store` — **الوحيد الذي يظهر فيه المفتاح**. تدقيق `key.create` (id, name, app).
- `DELETE /apps/{app}/keys/{id}` ⇒ 200 `{revoked:true}` أو 404؛ تدقيق `key.revoke` (id).
- تُسجَّل في `admin_routes()` (المصفوفة تغطيها).
