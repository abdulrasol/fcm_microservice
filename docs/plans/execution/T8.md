## المرحلة A — `src/send.rs`
```rust
#[async_trait] pub trait FcmTransport: Send + Sync {
    async fn send(&self, app:&str, project_id:&str, message:serde_json::Value) -> Result<FcmOutcome, SendError>;
}
pub enum FcmOutcome { Accepted{ body:String }, Rejected{ http_status:u16, body:String, dead_token:bool } }
pub enum SendError { Auth /* could not get an FCM access token */, Network }
pub struct HttpFcm { client: reqwest::Client, auth_map: AuthMap }   // the existing logic moved from main.rs
pub enum Destination { Token(String), Topic(String), Condition(String) }
pub fn build_message(title:&str, body:Option<&str>, image:Option<&str>, data:&BTreeMap<String,String>, analytics_label:Option<&str>, dest:&Destination) -> Value;
pub struct Delivery { pub delivered:usize, pub failed:usize, pub dead_tokens:Vec<String> }
pub async fn send_to_tokens(transport:&Arc<dyn FcmTransport>, app:&str, project_id:&str, tokens:&[String], make:impl Fn(&str)->Value, concurrency:usize) -> Delivery;
```
- `HttpFcm::send` = الكود الحالي حرفياً (scope `firebase.messaging`، URL v1، `bearer_auth`، timeout الحالي من العميل)، ويحدد `dead_token`.
- **تعريف الجهاز الميت (أضيق من الخطة عمداً):** الرد غير ناجح وجسمه JSON فيه `error.details[]` عنصر `errorCode == "UNREGISTERED"`، **أو** `error.status == "INVALID_ARGUMENT"` وفي `details[].fieldViolations[]` حقل ينتهي بـ`message.token`. أي `INVALID_ARGUMENT` آخر (محتوى/payload) ليس جهازاً ميتاً ولا يحذف شيئاً. وثّق هذا الانحراف عن 3.8 في التقرير والخطة.
- `send_to_tokens`: تزامن محدود (`tokio::task::JoinSet` + `Semaphore`، افتراضي 10)، لا يسجل التوكن، يجمع `dead_tokens`، و`failed` يشمل الشبكة/الرفض. لا يعيد المحاولة.
- أعد كتابة `send_notification` ليستعمل `build_message` و`state.fcm.send(...)` مع **نفس** رموز الأخطاء والرسائل والـJSON الحالية (502 لفشل التوكن/الشبكة، تمرير 4xx من FCM، حفظ topic عند النجاح...). سجّل خط الأساس قبل التعديل: اكتب اختبارات توصيفية (characterization) للسلوك الحالي **قبل** نقل الكود (commit مستقل) ثم تمر نفسها بعده.
- `AppState` يضيف: `fcm: Arc<dyn FcmTransport>`، `role_directory: Arc<RoleDirectory>`، `template_rate: Arc<TemplateRateLimiter>`. وتزول `#[allow(dead_code)]` عن كل ما صار مستعملاً (`devices`، `identity`، `datasource`، `config`) وأي دوال في `devices.rs`/`template.rs` صارت مستعملة (لا تعدّل تلك الملفات؛ إن بقي تحذير dead_code فيها فاذكره).

### قاعدة البيانات
في `migrate` (idempotent، واختبره مرتين):
1. `ALTER TABLE notifications_history ADD COLUMN kind TEXT` و`ADD COLUMN ref TEXT` — فقط إن لم يوجدا (تحقق بـ`PRAGMA table_info`).
2. `CREATE TABLE IF NOT EXISTS template_dedupe (app TEXT NOT NULL, template TEXT NOT NULL, key_hash TEXT NOT NULL, expires_at INTEGER NOT NULL, PRIMARY KEY(app, template, key_hash))` (+ `expires_at` بثواني UNIX).
3. دوال: `log_notification_ext(..., kind, reference)` و`log_notification` الحالية تستدعيها بـ`kind="raw"` دون تغيير توقيعها. `claim_dedupe(pool, app, template, key, seconds, now) -> Result<bool>` ذرّية (`INSERT ... ON CONFLICT DO UPDATE SET expires_at=excluded.expires_at WHERE template_dedupe.expires_at <= ?` وتعتمد `rows_affected()>0`؛ المفتاح يُخزَّن `sha256` hex لا نصاً). `release_dedupe(...)`. `purge_expired_dedupe(pool, now)` تُستدعى بالمصادفة عند كل claim (حد 1%) أو أبسط: DELETE للمنتهي داخل `claim` نفسه لنفس (app, template). `touch_template_used(pool, app, key)`: `UPDATE templates SET last_used_at = CURRENT_TIMESTAMP WHERE app=? AND key=?` **دون** المساس بـ`version`/`updated_at`/`definition`.
4. `TemplateRateLimiter`: في الذاكرة، مفتاح `(app, template, uid)`، نافذة منزلقة 3600 ثانية، الحد يمرَّر في كل استدعاء (`allow(key, limit) -> bool`)، حد أقصى 10 آلاف مفتاح (عند الامتلاء نظّف المنتهي ثم امسح الكل)، لا قفل عبر `await`.

## المرحلة B — المسار
`POST /api/v1/send/template`، جسم `{app, template, params?}` بـ`#[serde(deny_unknown_fields)]`، `params` كائن اختياري (افتراضي `{}`).
**الترتيب النهائي (انحراف مقصود عن ترتيب الخطة: المصادقة قبل كشف وجود القالب كي لا تُعدَّد أسماء القوالب بلا توكن):**
1. `app` معروف (إعداد محفوظ أو credentials) وإلا 404 (رسالة `ensure_known_app` نفسها)؛ حد IP عبر `topics::check_ip_limit`.
2. المرسل: Bearer = `SERVICE_API_KEY` ⇒ `Sender{uid:"service", name:None, role:None}` (يتخطى 5 و6). وإلا هوية عبر `authenticate_identity` (401/503، مع `auth_error_with_limit`)، والدور عبر `resolve_sender_role` (503 عند تعطل المصدر). المفتاح القديم أو أي سر غير مطابق ⇒ يُعامل كتوكن هوية فاشل (401).
3. `config.get(app)`: لا إعداد ⇒ 404؛ القالب غير موجود **أو** `enabled=false` ⇒ 404 بنفس الرسالة تماماً (`Template not found`).
4. غير service: الدور ∈ `template.senders` حرفياً وإلا 403 (أدمن الدور `admin` يلزم أن يكون مدرجاً صراحةً؛ لا استثناء ضمني). ثم الحد: `template.rate.per_uid_per_hour` (غائب ⇒ 120) عبر `TemplateRateLimiter` ⇒ 429.
5. `template::validate_params` ⇒ 400 (رسالة `BadRequest` كما هي).
6. إن وُجد `context`: `template::context_path` ثم `state.datasource.source_for(app)?.get_doc(path)`: `Unavailable` ⇒ 503 رسالة عامة بلا تفاصيل المصدر، `InvalidPath` ⇒ 400، `None` يُمرَّر كـ`None` إلى `render`.
7. `template::render(...)`: `Forbidden` ⇒ **403** برسالة ثابتة `Forbidden` (نفسها في الحالات الثلاث)، `BadRequest(m)` ⇒ 400 برسالة `m`.
8. تحقق `validation.rs` على الناتج: اقرأ `validate_send` وطبّقها بالوجهة الحقيقية لـ topic/condition؛ لهدفي uid/role مرّر وجهة token وهمية صالحة الشكل (ثابت مسمّى `VALIDATION_PLACEHOLDER_TOKEN` وتعليق يشرح السبب) فقط لتحقق المحتوى. فشل ⇒ 400.
9. dedupe (إن وُجد `dedupe_key`): `claim_dedupe` ؛ مكرر ⇒ **200** `{"status":"duplicate","delivered":0,"failed":0}` بلا أي إرسال.
10. المستلمون: `Uid` ⇒ `tokens_for_uid`؛ `Role` ⇒ `config.identity.role_members` غير مضبوط ⇒ 400 `role targets require identity.role_members`، وإلا `role_directory.uids_for_role` ثم `tokens_for_uids` بسقف 5000 (استعمل ما بُني في T6: `tokens_for_role`)، `DeviceError::Unavailable` ⇒ 503؛ `Topic`/`Condition` ⇒ رسالة FCM واحدة (ولا تُحفظ في جدول `topics` كما يفعل `/send`، بل فقط سجّل التاريخ).
    لا أجهزة ⇒ `release_dedupe` ثم **200** `{"status":"no_devices","delivered":0,"failed":0}`.
11. الإرسال عبر `send_to_tokens` أو رسالة واحدة. احذف الأجهزة الميتة (`remove_dead_token`). `touch_template_used` عند `delivered>0`. إن `delivered==0` ⇒ `release_dedupe`.
12. سجل التاريخ: صف واحد لكل طلب، `kind="template"`, `ref=<template>`, `target` نصي بلا توكنات (`uid:<id>` / `role:<r>` / `topic:<t>` / `condition`)، `payload` JSON للعنوان والنص والـdata المصيَّرة فقط (**لا توكنات، لا params خام**)، `response` ملخص `{"delivered":n,"failed":m}`، `sender_uid`.
13. الرد: `delivered>0` أو topic/condition مقبول ⇒ 200 `{"status":"success","delivered":n,"failed":m}`. `delivered==0 && failed>0` ⇒ 502 `{"status":"failed","delivered":0,"failed":m}`.
- الجسم محدود 64KB بالطبقة الحالية. لا تُسجَّل `params` ولا قيم الوثائق في `tracing`.
