# مرجع القوالب والحواجز الأمنية

يوثّق هذا المستند بنية قوالب الإشعارات في خادم FCM المصغّر، وقواعد لغة القوالب،
وحواجز الأمان المفروضة برمجياً لمنع تزوير الإشعارات أو إساءة استغلالها، وجدول
الرموز التشخيصية الكامل، مع ثلاثة أمثلة عملية جاهزة للاستخدام.

---

## 1. بنية تعريف القالب (Template Definition)

يُعرَّف كل قالب ككائن JSON تحت جدول `templates` لكل تطبيق (`app`) ويحتوي الحقول
التالية (كما هي في `src/config/mod.rs` و`src/config/validate.rs`):

| الحقل | النوع | إلزامي؟ | الوصف |
|---|---|---|---|
| `description` | نص | لا | وصف موجز لوظيفة القالب يظهر في لوحة التحكم (الحد الأقصى 200 حرف). |
| `enabled` | منطقي | نعم | حالة تفعيل القالب (`true`/`false`). عند التعطيل يُرد `404` عند محاولة استخدامه. |
| `senders` | مصفوفة نصوص | نعم | قائمة الأدوار المسموح لها بالإرسال عبر هذا القالب (مثل `["user", "admin"]`). |
| `params` | كائن | لا | خريطة المعاملات المدخلة من قِبل العميل مع قواعد التحقق الخاصة بها. |
| `context` | كائن | لا | مصدر بيانات الوثيقة المرجعية والتحقق من صلاحية الوصول إليها (`require`). |
| `vars` | كائن | لا | متغيرات وسيطة مشتقة من حقول الوثيقة عبر جداول تحويل (Mapping). |
| `to` | كائن | نعم | هدف الإرسال (`uid` أو `role` أو `topic` أو `condition`). |
| `title` | نص | نعم | نص عنوان الإشعار أو قالب معوض بحقول `{p.*}` أو `{doc.*}` أو `{sender.*}`. |
| `body` | نص | نعم | نص متن الإشعار أو قالب معوض. |
| `image` | نص | لا | رابط صورة الإشعار (يجب أن يبدأ بـ `https://`). |
| `data` | كائن | لا | حمولة بيانات مخصصة (`Key-Value`) تُسلَّم للتطبيق (لا تقبل مفاتيح FCM المحجوزة). |
| `dedupe` | كائن | لا | آلية منع تكرار إرسال نفس الإشعار خلال فترة زمنية محددة. |
| `rate` | كائن | شرطي | سقف معدل الإرسال (إلزامي إذا كان أحد `senders` دوراً غير إداري). |

### الأنواع الجاهزة

- **تنبيه للأدمن:** يوجّه الإشعار إلى دور `admin` ويتيح الإرسال للمستخدم والشركة والفني والأدمن. تعرض اللوحة الحقول اليومية فقط، وتضع البيانات والصورة والحدود ضمن «إعدادات متقدمة».
- **إشعار طلب:** يربط الإشعار بوثيقة `store_orders/{p.order_id}` ويتحقق من أن المرسل هو المشتري أو البائع، ثم يرسله إلى الطرف الآخر. تولّد اللوحة معامل الطلب وشروط الملكية ومنع التكرار وحد المعدل تلقائياً.
- **مخصص (متقدم):** يعرض صيغة القالب الكاملة لكل الحالات التي لا تطابق النوعين الجاهزين.

## 2. أنواع المعاملات (`params`)

تُحدَّد المعاملات التي يقبلها القالب من العميل تحت `params`، وتمنع الأداة إدخال
أي معامل غير مصرَّح به. يدعم المحرك أربعة أنواع:

| النوع | الخصائص | الاستخدام والقيود |
|---|---|---|
| `text` | `max: رقم` (1..=1000) | نص حر بحد أقصى للطول. يُعتبر "نصاً حراً" وتمنع الحواجز استخدامه في أهداف البث العام (`topic`/`condition`) لغير الأدمن. |
| `pattern` | `pattern: regex`, `max: رقم` (≤200) | نص مقيد بتعبير نمطي (مثل المعرفات الأبجدية الرقمية `^[A-Za-z0-9_-]{1,64}$`). لا يُعتبر نصاً حراً. |
| `enum` | `values: [نصوص]` (1..=50 قيمة) | اختيار من قائمة ثابتة من القيم المغلقة. لا يُعتبر نصاً حراً. |
| `int` | `min: رقم`, `max: رقم` | عدد صحيح يقع بين قيمتين محددتين. |

## 3. أنواع الهدف (`to`)

يحدد كائن `to` وجهة وصول الإشعار:

1. **مستند لجهاز مستخدم (`uid`):**
   `{"uid": "{doc.seller_id}"}` أو `{"uid": "{p.target_uid}"}`.
   يستعلم الخادم عن الأجهزة المسجلة لهذا الـ `uid` في جدول `devices` ويرسل إليها مباشرة.
2. **مستند لدور إداري (`role`):**
   `{"role": "admin"}`.
   يستعلم الخادم عن أعضاء الدور من مزود البيانات (`role_members`) ثم يجلب أجهزتهم النشطة.
3. **مستند لموضوع عام (`topic`):**
   `{"topic": "news"}` أو `{"topic": "{p.category}"}`.
4. **مستند لشرط منطقي (`condition`):**
   `{"condition": "'news' in topics && 'iq' in topics"}`.

> [!WARNING]
> إذا كان الهدف `topic` أو `condition`، وكان بين `senders` أدوار غير إدارية، فيُمنع
> منعاً باتاً احتواء القالب على أي معامل من نوع `text` أو بناء الهدف من نص حر (الحاجز `[G1]`).

## 4. لغة القوالب وعوامل التصفية

تعتمد لغة القوالب في `src/template.rs` على صيغة الأقواس المعقوفة مع منع التقييم المتداخل
(لا يمكن لقيمة قادمة من الخارج أن تُقيَّم كقالب مرة ثانية):

| الصيغة | المصدر | الوصف |
|---|---|---|
| `{p.<name>}` أو `{<name>}` | المعاملات | قيمة المعامل الممرر في الطلب؛ يجب تعريفه في `params`. |
| `{doc.<field>}` أو `{context.<field>}` | الوثيقة | قراءة حقل من وثيقة `context.doc` المجلوبة من مصدر البيانات (تدعم المسارات النقطية `doc.buyer.name`). |
| `{sender.uid}` | جلسة المصادقة | معرّف المستخدم الفعلي المستخرج من توكن الهوية JWT. |
| `{sender.name}` | جلسة المصادقة | اسم المستخدم المستخرج من claim المحدد في `name_claim`. |
| `{sender.role}` | نظام الأدوار | دور المستخدم المعتمد للتطبيق. |
| `{entity.<field>}` | وثيقة الكيان | حقول وثيقة الشركة في الحملات التسويقية. |
| `{<var>}` | جدول المتغيرات | قيمة مشتقة معرَّفة داخل `vars` (انظر أدناه). |
| `\|int` | مرشح عددي | تقريب الرقم للأقرب، مثلاً `{doc.total\|int}` يحول `1250.75` إلى `1251`. |

## 5. التحقق وسياق البيانات (`context` و`require`)

يوفّر قسم `context` إمكانية قراءة وثيقة حقيقية من مصدر البيانات (مثل Firestore أو HTTP Resolver)
قبل إرسال الإشعار، واستخدام حقولها في صياغة العنوان والمتن والهدف.

```json
"context": {
  "doc": "store_orders/{p.order_id}",
  "require": {
    "buyer_id": "{sender.uid}",
    "status": "pending"
  }
}
```

### حواجز وقواعد `require`:
1. **قاعدة التحقق الصارم المطابق:** يقارن الخادم كل حقل في `require` مع القيمة الناتجة بعد التعويض. إذا اختلفت قيمة أي حقل، أو كانت الوثيقة غير موجودة في مصدر البيانات، يُرد الطلب بـ **`403 Forbidden`** موحد.
2. **قاعدة منع المتغيرات (T13-A-5):** في حقول `require`، يُسمح بالقيم الثابتة والمعاملات `{p.*}` ومعلومات المرسل `{sender.*}` فقط (`Ref::Param | Ref::Sender`). يُمنع منعاً باتاً استخدام `{var}` أو `{doc.*}` داخل `require` (الرمز `[G6]`).
3. **أمان معرّف المرسل `[G4]`:** إذا كان القالب متاحاً لغير الأدمن، يجب أن يحتوي `require` على شرط واحد على الأقل يطابق `{sender.uid}` مع أحد حقول الوثيقة، مما يضمن ألا يرسل المستخدم إشعاراً عن طلب أو مورد لا يملكه شخصياً.

> [!IMPORTANT]
> **تنبيه أمني للمفاتيح (T8-F):**
> القوالب التي تعتمد `{sender.uid}` في `require` مخصصة حصراً للإرسال عبر توكن هوية المستخدم النهائي.
> إذا حاول خادم خلفي استدعاء هذا القالب باستخدام **مفتاح الخدمة** (`SERVICE_API_KEY`) أو **مفتاح التطبيق** (`fcm_<app>_...`)،
> فسيكون معرّف المرسل هو `service` أو `key:<id>`، وبالتالي سيفشل فحص `require` حتماً ويرد الخادم **`403 Forbidden`**.

## 6. المتغيرات المشتقة (`vars`)

تُستخدم لتحويل الحالات البرمجية الثابتة في قواعد البيانات إلى نصوص مفهومة للمستخدم:

```json
"vars": {
  "status_text": {
    "from": "doc.status",
    "map": {
      "shipped": "طلبك في الطريق إليك",
      "delivered": "تم تسليم الطلب بنجاح"
    }
  }
}
```
إذا كانت قيمة `from` غير موجودة ضمن مفاتيح `map`، يفشل التنفيذ ويرد الخادم بـ `400 Bad Request`.

## 7. منع التكرار (`dedupe`) وحدود المعدل (`rate`)

### 7.1 منع التكرار (`dedupe`)
```json
"dedupe": {
  "key": "{p.order_id}:{doc.status}",
  "seconds": 600
}
```
- يُحسب مفتاح القفل كـ `SHA-256(app + ":" + template + ":" + rendered_key)`.
- `seconds`: يجب أن تكون بين 1 و 86400 ثانية (يوم واحد) — الرمز `[T7]`.
- عند تكرار نفس المفتاح خلال الفترة، يرد الخادم بالاستجابة الناجحة السابقة دون إرسال إشعار جديد إلى FCM (`status: "duplicate"`).
- **قاعدة تحرير القفل (T8-F):** إذا فشل الطلب قبل التسليم (مثل عدم وجود أجهزة مسجلة للمستخدم، أو فشل الحصول على الاعتماد، أو سقوط مزود البيانات)، يُحرَّر مفتاح `dedupe` تلقائياً ليتمكن المستخدم من إعادة المحاولة.

### 7.2 سقف الإرسال (`rate`)
```json
"rate": {
  "per_uid_per_hour": 30
}
```
- إلزامي لأي قالب يحتوي على أدوار غير إدارية في `senders` (الرمز `[G3]`).
- يتتبع عدد الإرسالات لكل `uid` خلال نافذة ساعة منزلقة في SQLite. عند التجاوز يرد بـ `429 Too Many Requests`.

## 8. جدول الرموز التشخيصية الكامل (`[S*][G*][T*][V*][C*]`)

تُرجع واجهات التحقق (`POST /admin/apps/:app/templates/validate`) وواجهات حفظ الإعدادات قائمة
أخطاء منظمة تحمل رموزاً ثابتة لتسهيل إرشاد المستخدم في الواجهة:

| الرمز | التصنيف | المعنى والسبب |
|---|---|---|
| `[S1]` | بنية عامة | فشل قراءة JSON أو بنية الحقول غير مطابقة للنوع المطلوب. |
| `[S2]` | بنية عامة | اسم القسم المطلوب تحديثه غير معروف. |
| `[V1]` | إعدادات الهوية | اسم التطبيق غير مطابق للنمط `^[A-Za-z0-9_-]{1,40}$`. |
| `[V2]` | إعدادات الهوية | إعدادات مزود JWT غير صالحة (غياب الخوارزمية، خلط HS256 مع غيره، غياب متغير السر، أو صيغة claim غير صالحة). |
| `[V3]` | إعدادات الهوية | اسم الدور لا يطابق النمط المسموح `^[a-z0-9_]{1,32}$`. |
| `[V4]` | مصدر البيانات | تعارض إعدادات الأدوار مع `data_source = none` أو حقول غير مكتملة. |
| `[V5]` | مصدر البيانات | عنوان `base_url` غير صالح أو اسم متغير السر لا يطابق النمط. |
| `[V6]` | الأجهزة | سقف الأجهزة `devices.max_per_uid` خارج النطاق (1..=20). |
| `[V7]` | الاشتراك عبر الويب | نمط موضوع الاشتراك في `web_subscribe` غير صالح. |
| `[V8]` | أمان Firebase | تعارض إعداد App Check (يتطلب مزود firebase ورقم مشروع رقمي). |
| `[T0]` | بنية القالب | مفتاح القالب غير مطابق للنمط `^[a-z][a-z0-9_]{0,39}$`. |
| `[T1]` | بنية القالب | قائمة الأدوار المسموح لها بالإرسال `senders` فارغة. |
| `[T2]` | بنية القالب | تعريف خاطئ لأحد المعاملات (اسم غير مطابق، أو طول نص/تعبير خارج الحدود). |
| `[T3]` | بنية القالب | استخدام `{doc.*}` في القالب دون تعريف قسم `context`. |
| `[T4]` | بنية القالب | استخدام متغير أو حقل `{p.*}` غير معرّف مسبقاً في `params`. |
| `[T5]` | بنية القالب | تكرار اسم متغير مشتق في `vars`. |
| `[T6]` | بنية القالب | حقل بيانات في `data` يستخدم اسماً محجوزاً لـ FCM (مثل `from`, `notification`, `google.*`). |
| `[T7]` | بنية القالب | مدة منع التكرار `dedupe.seconds` خارج النطاق المسموح (1..=86400). |
| `[G1]` | حواجز الأمان | محاولة بث عام (`topic`/`condition`) بواسطة مستخدم عادي تحتوي على نص حر. |
| `[G2]` | حواجز الأمان | شرط `require` غير آمن أو لا يقرأ حقلاً من مستند السياق. |
| `[G3]` | حواجز الأمان | قالب متاح لغير الأدمن ولا يحتوي على سقف إرسال بالساعة `rate`. |
| `[G4]` | حواجز الأمان | سياق الطلب لغير الأدمن لا يحتوي على شرط يطابق `{sender.uid}` مع المستند. |
| `[G5]` | حواجز الأمان | متغير مشتق `var` يشير إلى حقل غير موجود أو غير معرّف. |
| `[G6]` | حواجز الأمان | استخدام متغير مشتق `{var}` داخل قسم `require` (ممنوع وفق T13-A-5). |
| `[C1]` | حملات الشركات | إعداد كيان الحملة غير مكتمل أو يفتقر للتحقق من ملكية الشركة بـ `{sender.uid}`. |
| `[C2]` | حملات الشركات | قائمة الجمهور `allowed_topics` غير صالحة أو تخالف نمط المواضيع. |
| `[C3]` | حملات الشركات | موضوع الحملات الإلزامي غير صالح أو عدد المواضيع يتجاوز الحد (2..=5). |
| `[C4]` | حملات الشركات | مخالفة قواعد محتوى الحملة (تجاوز طول العنوان/المتن أو مضيف صور غير معتمد). |
| `[C5]` | حملات الشركات | إجراءات الحملة `actions` فارغة أو تفتقر لفحص ملكية الإجراء عبر `{sender.uid}`. |
| `[C6]` | حملات الشركات | حصة الحملات اليومية أو الأسبوعية غير صالحة. |
| `[C7]` | حملات الشركات | إعدادات مراجعة الحملات `review.mode` غير صالحة. |

## 9. أمثلة كاملة

### 9.1 طلب جديد من مشترٍ إلى بائع (`order_new`)
يضمن هذا القالب أن المشتري وحده يستطيع إشعار البائع، وأن كافة بيانات الطلب والمستلم
تُجلب من وثيقة الطلب الموثوقة دون إمكانية إدخال نصوص تزويرية:

```json
{
  "description": "إشعار البائع بطلب جديد من المشتري",
  "enabled": true,
  "senders": ["user", "company", "technical"],
  "params": {
    "order_id": {
      "type": "pattern",
      "pattern": "^[A-Za-z0-9_-]{1,64}$",
      "max": 64
    }
  },
  "context": {
    "doc": "store_orders/{p.order_id}",
    "require": {
      "buyer_id": "{sender.uid}"
    }
  },
  "to": {
    "uid": "{doc.seller_user_id}"
  },
  "title": "طلب جديد #{doc.order_number}",
  "body": "طلب جديد من {doc.buyer_name} بقيمة {doc.total|int} {doc.currency}",
  "data": {
    "action": "open_order",
    "order_id": "{p.order_id}",
    "role": "seller"
  },
  "dedupe": {
    "key": "{p.order_id}",
    "seconds": 600
  },
  "rate": {
    "per_uid_per_hour": 30
  }
}
```

### 9.2 تنبيه إداري من أي مستخدم للأدمن (`admin_alert`)
يُستخدم لإرسال بلاغات أو تنبيهات إدارية من المستخدمين إلى كافة المشرفين:

```json
{
  "description": "تنبيه لإدارة النظام من المستخدمين المسجلين",
  "enabled": true,
  "senders": ["user", "company", "technical", "admin"],
  "params": {
    "title": { "type": "text", "max": 80 },
    "body":  { "type": "text", "max": 300 },
    "route": { "type": "pattern", "pattern": "^/[a-z0-9/_-]*$", "max": 100 }
  },
  "to": {
    "role": "admin"
  },
  "title": "{p.title}",
  "body": "{p.body}",
  "data": {
    "action": "open_page",
    "target": "{p.route}"
  },
  "rate": {
    "per_uid_per_hour": 10
  }
}
```

### 9.3 تحديث حالة الطلب من البائع للمشتري (`order_status`)
يوضح استخدام قسم `vars` لتحويل الحالات البرمجية إلى عبارات عربية موحدة:

```json
{
  "description": "إشعار المشتري بتغير حالة طلبه",
  "enabled": true,
  "senders": ["company", "technical", "user"],
  "params": {
    "order_id": {
      "type": "pattern",
      "pattern": "^[A-Za-z0-9_-]{1,64}$",
      "max": 64
    }
  },
  "context": {
    "doc": "store_orders/{p.order_id}",
    "require": {
      "seller_user_id": "{sender.uid}"
    }
  },
  "vars": {
    "status_text": {
      "from": "doc.status",
      "map": {
        "confirmed": "تم تأكيد طلبك #{doc.order_number} بنجاح",
        "preparing": "طلبك #{doc.order_number} قيد التجهيز",
        "shipped":   "تم شحن طلبك #{doc.order_number} وهو في الطريق إليك",
        "delivered": "تم تسليم طلبك #{doc.order_number} بنجاح",
        "cancelled": "تم إلغاء طلبك #{doc.order_number}"
      }
    }
  },
  "to": {
    "uid": "{doc.buyer_id}"
  },
  "title": "تحديث الطلب #{doc.order_number}",
  "body": "{status_text}",
  "data": {
    "action": "open_order",
    "order_id": "{p.order_id}",
    "status": "{doc.status}"
  },
  "dedupe": {
    "key": "{p.order_id}:{doc.status}",
    "seconds": 600
  },
  "rate": {
    "per_uid_per_hour": 120
  }
}
```
