# 🤖 Agent Instructions (for AI Assistants)

Welcome, fellow AI Assistant. If you are reading this, you have been tasked with reading, modifying, or maintaining this Rust microservice. Please adhere to the following rules and architecture guidelines.

## 🏗️ Architecture Overview
1. **Purpose:** A proxy to send Firebase Cloud Messaging (FCM) notifications using the **FCM HTTP v1 API**. It protects the Firebase Service Account JSON from being exposed to client apps.
2. **Language & Framework:** Rust + `axum` + `tokio`.
3. **HTTP Client:** `reqwest`.
4. **Google Auth:** `yup-oauth2` is used to read the `service-account.json` and generate ephemeral Bearer tokens.
5. **Deployment:** Multi-stage Docker build targeting Alpine for minimal image size.

## 📜 Strict Coding Guidelines
1. **DO NOT USE FCM Legacy API:** The legacy API (`https://fcm.googleapis.com/fcm/send`) is deprecated by Google. You must **always** route requests to `https://fcm.googleapis.com/v1/projects/{project_id}/messages:send`.
2. **FCM v1 Payload Rules:** 
   - The FCM v1 payload requires all notification details to be wrapped inside a `"message"` object.
   - The `"data"` payload in FCM v1 strictly accepts **only string values**. If the client sends integers or booleans in the `"data"` field, the Rust service *must* convert them to strings before forwarding to Firebase. This logic is already implemented in `src/main.rs`. Do not remove it.
   - Example valid structure:
     ```json
     {
       "message": {
         "topic": "all",
         "notification": { "title": "...", "body": "..." },
         "data": { "key": "value_as_string" }
       }
     }
     ```
3. **Authorization:** 
   - The `/api/v1/send` endpoint expects the client to provide an `Authorization: Bearer <API_KEY>` header.
   - This `API_KEY` is compared against the `API_KEY` environment variable. Do not bypass this check unless explicitly requested by the user.
4. **Rust Best Practices:**
   - Always use `Arc` for shared state (e.g., `Arc<AppState>`).
   - Use `tracing` for logs (`tracing::info!`, `tracing::error!`). Do not use `println!`.
   - Ensure you use robust error handling. Map internal errors to `(StatusCode, String)` tuples for `axum` responses.

## 🛠️ Testing & Running
- To run locally without Docker:
  ```bash
  cargo run
  ```
  *(Make sure `.env` and `service-account.json` exist locally).*
- To format code: `cargo fmt`
- To run linter: `cargo clippy`

End of instructions. Keep it fast, keep it memory-safe! 🦀
