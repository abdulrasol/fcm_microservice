# FCM Microservice Agent Context

This repository is a Rust-based microservice and integrated web dashboard for managing and sending Firebase Cloud Messaging (FCM) notifications across multiple Firebase projects.

## Architecture Guidelines
- **Backend**: Rust using `axum`, `tokio`, `sqlx` (SQLite), and `notify` (File watching).
- **Frontend**: Lightweight static SPA (e.g., Vite/React) served by the Rust backend on `/`.
- **Database**: SQLite (`data.db`) used strictly for notification history and saved topics.
- **Credentials**: Multi-tenant Firebase architecture. Service account JSON files are placed in `credentials/`. The system monitors this folder dynamically.
- **Routing**: `/api/v1/*` is reserved for backend API endpoints. All other routes should serve the static frontend.

## Key Principles
- **Efficiency**: The system must remain extremely lightweight, minimizing CPU and memory usage.
- **Security**: Admin endpoints require a verified Firebase ID token (RS256) plus `users/{uid}.role == "admin"` in Firestore, or an optional server-side `SERVICE_API_KEY`. No shared secret is shipped to clients. The legacy `API_KEY` is disabled by default and accepted only on `/send` while `LEGACY_API_KEY_ENABLED=true`. Public topic subscriptions are limited to `all`, `country_<2 letters>` and `lang_<2 letters>`.
- **Reusability**: The API is designed to be used headless by external applications, mandating the explicit passing of the `"app"` field in payloads.
